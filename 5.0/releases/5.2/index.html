    Release notes#

    The releases of Hopsworks 5.2, newest first.

    5.2.3#

    Helm chart 5.2.3 · Released on 2026-10-29 · Changes since 5.2.2 · Python client 5.2.2, unchanged

    Breaking changes#

    • HELM Mirror envoyproxy/envoy:v1.38.0 to the path envoyproxy/envoy of your registry before the upgrade when global._hopsworks.imageRegistry points at your own: Python apps now pull their Envoy sidecar from that registry instead of Docker Hub, so air-gapped installs can start them (Envoy image of Python apps).

    Upgrade steps#

    Follow Changes from 5.2.3 in the upgrade guide.

    Configuration changes#

    • HELM Added hopsworks.variables.python_app_envoy_image_version (default v1.38.0), the tag of the Envoy sidecar of Python apps (values).

    Python client#

    The Python client is unchanged, 5.2.2.

    5.2.2#

    Helm chart 5.2.2 · Released on 2026-10-28 · Changes since 5.2.1 · Python client 5.2.2

    What's changed#

    • API Addressed vulnerabilities in the ArrowFlight server.
    • API FRONTEND Addressed vulnerabilities in the Trino and Superset services of projects.
    • API Fixed the OTLP sidecar of agent deployments with tracing running out of memory under ordinary traffic, which took the deployment out of service while the sidecar restarted; the sidecar now drops telemetry it can't keep up with instead of buffering it (OTLP sidecar).
    • API FRONTEND HELM Fixed Python app pods staying in ContainerCreating after their execution ended; an app that was ready now ends only after hopsworks.variables.pythonapp_unready_timeout_seconds (600) without a ready container.
    • API FRONTEND HELM Added GPU scheduling through NVIDIA Run:ai (hopsworks.variables.run_ai_enable, off by default), which binds every project to a Run:ai project so that Run:ai quotas, fair share and preemption apply to its pods, shows the project's GPU quota in the UI and adds Project.get_gpu_availability() to the Python client, which reports the cluster's GPUs when Run:ai is off; it can't be combined with Kueue (Run:ai).
    • API FRONTEND HELM Added SharePoint data sources, which copy a folder of a SharePoint Online document library into a project dataset once or on a schedule, also with SharePointConnector.create_sync and copy_folder in the Python client and hops datasource sharepoint; hopsworks.variables.enable_sharepoint_storage_connectors turns them off (SharePoint).
    • API FRONTEND HELM Added Hopsworks data sources, which read the feature groups of a project on another Hopsworks cluster through ArrowFlight, as external feature groups or with dltHub ingestion, also with hops datasource create hopsworks; hopsworks.variables.enable_hopsworks_storage_connectors turns them off (Hopsworks data source).
    • API FRONTEND Added Microsoft SQL Server and Azure SQL Database as SQL data sources, read through Spark, ArrowFlight, Trino catalogs and dltHub ingestion (SQL Server).
    • API FRONTEND Added departments, which group projects: administrators create them and move projects between them in the cluster settings, and hopsworks.create_project in the Python client takes a department.
    • API FRONTEND HELM Changed public (no-login) access to apps to cover every kind of app instead of only Streamlit apps, turned on by hopsworks.variables.enable_public_apps (public access).
    • API FRONTEND Added a table viewer to the Apps page, and the dropping of an app's tables when the app is deleted, for apps created from 5.2.2 on, which create their tables with App.create_table and change them with App.alter_table in the Python client (database access).
    • API Added limit to FeatureGroup.read and ExternalFeatureGroup.read in the Python client, and changed limited reads through ArrowFlight, such as show(n) and hops fg preview, to stop after that many rows instead of reading the whole feature group.
    • API FRONTEND Fixed starting a terminal, notebook, Python job, Python app or deployment without enough project quota being accepted and then failing without a reason; the start is now refused with Project quota exceeded, and the Jupyter, Jobs and Deployments pages show the project's quota.
    • API FRONTEND Fixed saving a Python app on a cluster with Kueue failing with Queues in Kueue are not supported for:PythonApp.
    • API FRONTEND Fixed the Spark properties of a job or a Jupyter server written with spaces around =, such as spark.executor.cores = 2, being ignored.
    • API Fixed get_feature_groups without a name in the Python client returning external feature groups and spine groups as managed ones, so get_external_feature_groups without a name returned none.
    • API Fixed hops fg create-external saving the feature group without its --query or --path, added --features and --online to it and --type to hops fg list, and changed the type label of managed feature groups in hops fg list and hops fg info from cached to managed.
    • API Fixed hopsworks.login() and Kafka inserts failing with FileNotFoundError on Windows, where the Python client used /tmp.
    • API Fixed waiting for an online ingestion of no rows in the Python client lasting until its timeout, or forever with timeout 0.
    • API FRONTEND Fixed apps whose name makes their Deployment name longer than 54 characters never scaling to zero when idle.
    • FRONTEND Addressed vulnerabilities in Jupyter, Python apps, the Spark UI and the Ray dashboard.
    • FRONTEND HELM Added Compute Allocation to the cluster settings of a cluster with Kueue, where administrators set the compute each department and project is guaranteed and can borrow, which Hopsworks applies as Kueue Cohorts and ClusterQueues, and follow its use. It needs global._hopsworks.kueue.queueModel: per_project, set at install; moving a running cluster from shared, the default, is not supported.
    • FRONTEND HELM Added editing of node labels and priority classes to the Kubernetes Scheduler cluster settings, once hopsworks.rbac.nodeLabels.edit and hopsworks.rbac.priorityClasses.edit grant Hopsworks the permissions, both off by default. hopsworks.rbac.nodeLabels.edit grants patch on every node, which Kubernetes RBAC can't limit to labels, so it also allows changing taints.
    • FRONTEND Changed Extract in the file browser to unzip or untar an archive in a background Terminal tab, instead of in a Spark job that copied it to a node's local disk and could fill it; without the Terminal it still runs the job.
    • FRONTEND Added the selection of several files in the file browser, by dragging, Ctrl or Cmd-click and Shift-click, and their deletion with Delete or the Delete key.
    • FRONTEND Added cancelling uploads in the file browser, per file or with Cancel all.
    • FRONTEND Added sorting a dataset in the file browser by Last update and Author, and fixed going up to the dataset root after sorting a folder failing with HTTP 404.
    • FRONTEND Added a show shared switch to the feature group list, which hides the feature groups shared with the project.
    • FRONTEND Added a Project limit reached notice to the create project page, which turns off Create New Project once the user has reached their project limit, instead of showing only the error of a failed create.
    • FRONTEND Fixed the Add members dialog saying every user is already a member on clusters with user search disabled.
    • FRONTEND Fixed Test connection of Oracle data sources showing Connection Failure for a connection that works.
    • FRONTEND Fixed the admin Users page not scrolling, which left most users out of reach, and added a sortable Last login column.
    • FRONTEND Fixed error messages that were empty or generic for many failed actions, and 502 and 503 errors showing the raw HTML page of the ingress.
    • FRONTEND Fixed a feature store shared with a project, or unshared from it, showing the change only after logging out and in again.
    • FRONTEND Fixed a failed Jupyter start showing an exception class name, such as KubeException, instead of the reason.
    • HELM Fixed Airflow on 5.2.0 and 5.2.1 having no task_reschedule table, and the upgrade from 5.1 emptying the Airflow tables after it, such as variables and XComs; the upgrade to 5.2.2 creates the missing table, and a failed conversion now fails the Airflow migrate Job. Rows that an earlier upgrade to 5.2.0 or 5.2.1 lost are not restored: re-create them or restore them from a backup.
    • HELM Fixed an OpenSearch snapshot restore leaving the .opendistro_security index closed, after which OpenSearch crash-loops (recover a cluster restored on 5.2.0 or 5.2.1).
    • HELM Fixed a fresh helm install --wait hanging when it ran more than an hour after the Trino auth seed Job finished, because the Job's TTL deleted it.
    • HELM Added support for Kubernetes 1.33, which the chart refused below 1.34.
    • HELM Changed the KEDA CRD upgrade hook to read the CRDs from the hopsworks/keda-crds image (hw-keda.crdUpgradeJob.image) instead of a hook ConfigMap, which took 13% of the 1 MiB Helm release Secret; mirror that image on an airgapped cluster (KEDA CRDs).
    • HELM Moved the upgrade guide and the Helm 4 migration notes from the chart's UPGRADE.md and HELM4_MIGRATION.md to the docs (upgrading Hopsworks, upgrading with Helm 4).
    • HELM Fixed the Jobs of the VPA install and uninstall, the Kueue objects, the Trino auth seed, the Airflow key bootstrap, Velero backups and the OpenSearch reindex ignoring global._hopsworks.nodeSelector and global._hopsworks.tolerations, and the wipe Job ignoring global._hopsworks.nodeSelector (dedicated node pools).
    • HELM Fixed the TooManyShards alert never firing; a cluster above 90% of its shard limit starts alerting after the upgrade.
    • Addressed vulnerabilities in the Hopsworks server image and its dependencies, the UI dependencies and the database migration image.
    • Addressed vulnerabilities in the Superset, Prometheus, Grafana, OpenSearch Dashboards, OpenSearch metrics exporter, Logstash and Trino images.
    • Addressed vulnerabilities in the Python environment base images and in the Airflow, terminal, Kafka, Vertical Pod Autoscaler, Spark operator CRD, KServe, KEDA HTTP add-on, remote shuffle service init and BuildKit images.
    • Fixed the statistics cleaner's query taking an hour or more per run on clusters with many feature statistics, during which it blocked the schema migrations of the statistics tables.
    • Fixed the Superset Redis being OOM-killed every few hours by zombie processes its health probes left behind.
    • Changed the RonDB REST server to size its buffer pool from its memory limit, return idle buffers after 15 minutes and opt out of transparent huge pages, so that its memory stays bounded.

    Breaking changes#

    • API FRONTEND HELM Changed how OnlineFS checks the topic of the records it writes, to address a vulnerability (what this affects). Restart the producers that hold on to a topic after it changes; on a Kafka where records reach OnlineFS on a renamed topic, such as a mirrored secondary, set onlinefs.configmapOverrides.onlinefssite.service.verifyFeatureGroupTopic: false.
    • API FRONTEND On a cluster with Kueue, Spark jobs are now queued by Kueue and run with static executors instead of dynamic allocation: a job saved with dynamic allocation runs its dynamic-allocation minimum, at least one executor, and spark.dynamicAllocation.enabled=true is refused; set spark.executor.instances for more executors (what changes).
    • API FRONTEND The upgrade deletes the Deployment of every Python app whose executions have all ended, also one that still answers requests; start such an app again to keep it running.
    • API FRONTEND Apps created from 5.2.2 on can only read the online feature store database, apart from the tables they create with App.create_table and change with App.alter_table in the Python client, or with createTable and alterTable of @hopsworks/app in Node.js; before, the apps of Data Owners could create, alter and write to any of its tables with their own SQL (database access).
    • API Python clients older than 5.2.2 fail to list the data sources of a feature store that has a Hopsworks or SharePoint data source; use the 5.2.2 client in the jobs and environments that list them (client version).
    • API FRONTEND Ingestion from a MongoDB data source, and fetching its schema, now needs MongoDB 4.4 or later instead of 4.2.
    • FRONTEND Because of a security fix, open Jupyter servers from the Hopsworks UI.
    • FRONTEND Because of a security fix, give a Python app that calls Hopsworks credentials of its own, such as an API key.
    • HELM Hopsworks now uses Kueue 0.20.3 installed as its own release, kueue in kueue-system, instead of the Kueue 0.12.2 bundled in its namespace, and the chart refuses to render while the bundled Kueue still runs (Kueue outside the Hopsworks namespace). With global._hopsworks.kueue.enabled: true, move Kueue with the 5.1 chart's migrate-to-external.sh before the upgrade, run the chart's upgrade-kueue.sh after it, and remove hw-kueue.managerConfig, hw-kueue.nameOverride and every hw-kueue.kueue value but enabled from your values, or the values schema rejects the upgrade.
    • HELM Remove rondb.rondb.rdrs.internal.bufferSize, gomaxprocs and maxAllocatedBuffers from your values, which the chart ignored, or helm upgrade fails before changing anything.
    • HELM The hopsworks, HopsFS and Hive schema migrations now run on the DDL SQL node instead of the application SQL nodes, so they no longer wait for application queries; a cluster that disables it (rondb.rondb.meta.ddlMySQLd.enabled: false) sets hopsworks.dependencies.mysql.ddlConsulServiceName, hopsfs.dependencies.mysql.ddlConsulServiceName and hive.metastore.dependencies.mysql.ddlConsulServiceName to mysql, or the migrations wait for a SQL node that doesn't exist (DDL SQL node).
    • HELM The chart package no longer ships values.aws.yaml, values.azure.yml, values.gcp.yaml, values.rhel8.yaml and values.nodeselector-tolerations.yaml; keep a copy of the one you pass, or start from the values file of the AWS, Azure or GCP setup guide and take the RHEL 8 and node pool values from Python build performance and dedicated node pools.

    Deprecations#

    • HELM Deprecated hopsworks.variables.streamlit_sharing; use hopsworks.variables.enable_public_apps, which covers every kind of app, and true in either one turns public access on.

    Configuration changes#

    • HELM Changed the memory request and limit of the RonDB REST server pods (rondb.rondb.resources.requests.memory.rdrsMiB, rondb.rondb.resources.limits.memory.rdrsMiB) from 100 MiB and 500 MiB to 2 GiB; check node capacity before the upgrade.
    • HELM Changed the default of hopsworks.variables.agent_deployment_otel_memory_mb, the memory request and limit of the OTLP sidecar of traced agent deployments, from 1024 to 2048. Each traced agent deployment reserves it on its node once it is recreated, so check node memory before you redeploy them (OTLP sidecar).

    • HELM The post-upgrade search index rebuild signs in as the agent user, instead of with hopsworks.variables.admin_email and admin_password, and fails the helm upgrade if hopsworks.agent_email and hopsworks.agent_password (default agent@hops.io, admin) don't match that account (also in 5.1.1). Set them, or turn the rebuild off with hopsworks.opensearchReindex.enabled: false.
    • HELM With Helm 4, pass --skip-crds to a helm install on a cluster that already has the Strimzi CRDs, and after a reinstall run helm upgrade once to recreate the KEDA CRDs (Strimzi CRDs, KEDA CRDs).
    • HELM If your values restate trino.trino.additionalConfigProperties with its event-listener.config-files entry, which the 5.1.1 chart set by default, remove that entry or add the listener files as Trino query history shows, or Trino doesn't start (also in 5.1.2).
    • HELM Overrides of the Trino initContainers, additionalVolumes or additionalVolumeMounts, including those 5.1.0 asked for with hopsworks.hopsfsMount.enabled: false, fail the render; remove the overrides, or copy the new entries from the chart into them.
    • HELM Under ArgoCD with trino.auth.createSecrets on (the default), set trino.auth.adminUserPwd and trino.auth.monitoringUserPwd to the passwords of your 5.1 release, which now default to empty instead of fixed passwords, or the chart fails to render; a helm upgrade outside ArgoCD reuses the existing Secrets whatever global._hopsworks.mode is.
    • HELM If you set trino.trino.serviceAccount.name, set trino.trinotest.serviceAccount.name to the same name, because the test coordinator now shares the Trino account instead of creating its own hopsworks-trino-test, or the chart fails to render.
    • HELM If your values override trino.trino.accessControl.rules, merge the rules of the 5.2 chart into your copy, because the backend now builds the Trino access rules from that value and the 5.1 rules leave out the private (_<user>__*) catalogs and give the admin group every catalog.
    • HELM If you override trino.trino.image.tag, use a Hopsworks Trino image of 483-v2 or later instead of the 480 images of 5.1, and set global._hopsworks.trino.image.tag to the same tag.
    • HELM With cluster backups on, Superset backups, new in 5.2, need an object store and, with superset.auth.createSecrets: false, the backup.hops.works/include=true label on its Secrets, or the chart fails to render; set superset.backups.enabled: false to skip them (disaster recovery).
    • HELM Removed the KServe local model controller; if you set kserve.kserve.localmodel.enabled: true, remove it, or the chart fails to render.
    • HELM If your release namespace is longer than 34 characters, set global._hopsworks.csi.driverName, because the default name of the HopsFS CSI driver, new in 5.2, would exceed 63 characters (driver name).
    • HELM On OpenShift, use the values.openshift.yaml of the 5.2 chart, which creates an SCC for the privileged HopsFS CSI node plugin, new in 5.2; if a cluster administrator owns SCCs, see when the cluster administrators own the SCC.
    • HELM Project namespaces now get a NetworkPolicy that admits traffic only from the same namespace and the Hopsworks namespace, where 5.1 restricted only web terminal pods; add any other namespace that reaches project pods, such as Istio or monitoring, to hopsworks.variables.project_namespace_network_policy_allowed_namespaces (values). Turning them off with hopsworks.variables.project_namespace_network_policy_enabled: false leaves the existing ones; delete them with kubectl delete networkpolicy -A --field-selector metadata.name=hopsworks-project-isolation.
    • HELM With hopsworks.rbac.useExistingRole: true, add the chart's new ClusterRole grants (charts/hopsworks/templates/role.yaml) on scaledobjects, interceptorroutes, ingresses, networkpolicies and csidrivers, or model deployments, project creation and every pod that mounts HopsFS fail.
    • HELM The RonDB REST server now uses a probe port and an upload path that need RonDB 26.02.11, where 5.1.0 probed its REST port and set no upload path (also in 5.1.1). If you pin rondb.rondb.images.rondb.tag to an older version, set rondb.rondb.rdrs.probePort.enabled: false and rondb.rondb.rdrs.uploadPath: "", or the REST server doesn't start.
    • HELM Kafka 4.3 rejects clients older than Apache Kafka 2.1 or librdkafka 1.8.2, which the Kafka 3.9 of 5.1 accepted; upgrade them first; with your own Kafka cluster, its brokers must run Kafka 2.1 or later (client compatibility).
    • HELM OpenSearch now reports its own version, 3.8.0, instead of 7.10.2; check clients that connect to it directly against the OpenSearch 3.0 breaking changes.

    Deprecations#

    • API Deprecated entry of get_feature_vector, get_feature_vectors, get_inference_helper and get_inference_helpers in the Python client; use serving_keys.
    • API Deprecated Deployment.environment in the Python client; use predictor.environment and transformer.environment.
    • API Deprecated source="opensearch" of Deployment.read_logs and tail_logs in the Python client and --source opensearch of hops deployment logs and hops agent logs, whose default is now kubernetes instead of opensearch.
    • API Deprecated spine groups (get_or_create_spine_group) and the spine argument of FeatureView reads in the Python client; use spine_df.
    • API Deprecated ModelSchema in the Python client; a model created with create_model(feature_view=...) takes its schema from the feature view, and a deployment describes its requests with the deployment schema.
    • API Deprecated hops init; use hops skills install.
    • API Deprecated the environmentDTO field of model deployments in the REST API; use predictorEnvironment and transformerEnvironment.
    • HELM Deprecated the name of kafka.cluster.zookeeper, which now sizes and places the KRaft controllers; its services.client.annotations is no longer read.
    • HELM Deprecated hopsworks.variables.mount_hopsfs_in_python_job, which only legacy Python jobs still read.
    • HELM Deprecated global._hopsworks.trino.mountableSecrets.mechanism, global._hopsworks.trino.userCatalogShards, trino.auth.adminUserPwdHash, trino.auth.monitoringUserPwdHash and hw-kyverno.policyExceptions.trino, which nothing reads any more.
