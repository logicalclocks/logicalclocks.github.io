    Release notes#

    The releases of Hopsworks 5.0, newest first.

    5.0.14#

    Helm chart 5.0.14 · Released on 2026-10-16 · Changes since 5.0.13 · Python client 5.0.10

    What's changed#

    • API FRONTEND Fixed queued project and member operations, such as Superset access changes, failing for good after 68 attempts, for project Observers, or when removing a member's Superset user; a failing operation now retries once a day.
    • API Changed Spark engine reads of a feature view whose feature groups all come from one Snowflake data source to run the whole query, point-in-time joins included, in Snowflake instead of reading each feature group in full.
    • API FRONTEND Added key pair authentication to DLT ingestion from Snowflake, which accounts that enforce MFA need (Snowflake data source).
    • API Fixed reads of external feature groups failing on chained point-in-time joins, on joins with a prefix or extra primary keys, and, in the Python engine, when they leave out a feature appended to the feature group.
    • API Fixed external Spark clients failing to read, write or delete DELTA feature groups when the HopsFS NameNode and DataNode load balancers are disabled.
    • API Fixed the Python client installing pyarrow 26 next to NumPy 1, with which importing hsfs.feature_group fails with pyarrow requires NumPy 2.0 or newer; it now requires pyarrow below 26.
    • API FRONTEND Fixed Trino giving a project access to only one of several feature stores shared with it.
    • API FRONTEND Fixed a new project that reuses the name of a project still being deleted losing its members' Trino and Superset access and its dataset shares when the old project's delete ran.
    • API FRONTEND Fixed Git operations failing with an I/O error when a Git provider proxy is set on a cluster with HopsFS encryption at rest.
    • API FRONTEND Fixed a killed Spark job with pending executors staying in the aggregating logs state for up to 20 minutes.
    • API Fixed SnowflakeConnector.connector_options() in the Python client failing for a data source with key pair authentication, and leaving out the role set on the data source.
    • API Fixed Snowflake reads through the Hopsworks Query Service, such as Python engine reads, using the Snowflake user's default role instead of the role set on the data source.
    • API FRONTEND Fixed DLT ingestion rejecting a load whose decimal values are narrower than the precision of the source column.
    • FRONTEND Added a Stop button to the SQL Runner, and leaving the SQL Runner now stops the running query; the run status shows the elapsed time and the rows the query engine processed.
    • FRONTEND Changed the SQL Runner layout: the results fill the panel with row numbers and column types, the Explorer lists a table's columns, autocomplete completes the statement at the cursor, EXPLAIN plans render as JSON or a graph, and long plans and table definitions scroll instead of overflowing.
    • FRONTEND Fixed dialogs, drawers and menus opened from a table row closing by themselves on the Git, model deployment, alert receiver and feature monitoring pages, and the Git Status drawer never opening.
    • HELM Fixed RonDB daemons ignoring SIGTERM, so every pod stop ended in a kill and a stopped data node could stall the cluster.
    • HELM Changed the RonDB REST server probes to use their own port, which keeps answering while a stalled data node blocks requests.
    • HELM Fixed the RonDB REST server reading request bodies over 64 KiB as empty.
    • Addressed vulnerabilities in the Payara, Hopsworks, Hopsworks CA, Hive Metastore, remote shuffle service, Spark operator, Filebeat, Logstash, Grafana, OpenSearch Dashboards and Superset images, in the MySQL and Redis of Superset, and in the Hopsworks server dependencies.
    • Fixed HopsFS staying in safe mode after all NameNodes restarted, a NameNode restart occasionally marking every block as corrupt, and NameNodes running out of file descriptors when many blocks are corrupt.

    Breaking changes#

    • API FRONTEND Because of a security fix, Data Scientists ask the creator of a job or a Data Owner of the project to change it, other than its schedule.
    • HELM The chart no longer turns on Trino's MySQL event listener, which crash-looped the Trino coordinator after a MySQL server restart, so the Trino query history stops recording queries. To keep it, add the listener to your values as the chart's README.md shows; recorded queries now lose their text and plan after hopsworks.variables.trino_events_strip_details_after_days, from the first nightly cleanup, so set it to 61 or more to keep them.
    • HELM If your values restate trino.trino.additionalConfigProperties with its event-listener.config-files entry, which the 5.0.13 chart set by default, remove that entry or add the listener files as the chart's README.md shows, or Trino doesn't start.
    • HELM The RonDB REST server now uses a probe port and an upload path that need RonDB 26.02.11, instead of probing its REST port with no upload path. If you pin rondb.rondb.images.rondb.tag to an older version, set rondb.rondb.rdrs.probePort.enabled: false and rondb.rondb.rdrs.uploadPath: "", or the REST server doesn't start.

    • HELM Removed the MySQL event listener from the default trino.trino.additionalConfigProperties and from trino.trino.coordinator.additionalConfigFiles and trino.trino.worker.additionalConfigFiles.

    • HELM Added rondb.rondb.rdrs.ttlPurge.enable and activeWindow to turn off the TTL purge of the RonDB REST server or limit it to a daily window.

    5.0.13#

    Helm chart 5.0.13 · Released on 2026-09-28 · Changes since 5.0.12 · Python client 5.0.9, unchanged

    What's changed#

    • API Fixed offline reads of a feature view or query that includes a spine group failing with an HTTP 500 error.
    • HELM Fixed the Airflow migration Job losing tables on clusters with more than one RonDB MySQL server, so the upgrade never completed; it now uses only the DDL MySQL server. A cluster whose earlier upgrade already failed this way needs the Airflow schema dropped on every MySQL server before it upgrades again.
    • HELM Fixed OnlineFS upgrades stalling on a full node pool: with two or more onlinefs.deployment.replicas, a rollout now replaces one pod at a time.
    • HELM Changed the RonDB REST server probes to outlast a data node failure.
    • HELM Fixed the OpenSearch metrics exporter reporting the parent cluster on a satellite deployment, and missing OpenSearch with a custom global._hopsworks.consulDomainName.

    Breaking changes#

    • HELM The Airflow migration Job now waits for the DDL MySQL server, instead of any MySQL server, so the upgrade hangs with rondb.rondb.meta.ddlMySQLd.enabled: false. Keep it enabled if you use Airflow.
    • HELM Removed the Kafka quota defaults Job, which applied kafka.cluster.kafka.quotas.defaults to each client, so it is ignored with type: strimzi, and fails the render with type: kafka when enabled is true. If you set it, move your limits to kafka.cluster.kafka.quotas.strimzi or kafka.cluster.kafka.quotas.kafka, with new numbers: the strimzi rates are a total per broker, shared by all clients.
    • HELM quotas on a user in kafka.users now fail the render under the default strimzi plugin, which never enforced them. Remove them, or set kafka.cluster.kafka.quotas.type: kafka, kafka.cluster.kafka.quotas.minAvailableRatioPerVolume: 0 and kafka.cluster.kafka.authorizer.principalBuilderClass: "" to enforce them.

    Deprecations#

    • HELM Deprecated kafka.cluster.kafka.quotas.defaults, which is no longer honoured; see the breaking changes above.

    Configuration changes#

    • HELM Added kafka.cluster.kafka.quotas.type to choose the Kafka quota plugin: strimzi (the default), set under kafka.cluster.kafka.quotas.strimzi, or kafka, which enforces per-user quotas from kafka.users[].quotas and defaults from kafka.cluster.kafka.quotas.kafka. kafka also needs kafka.cluster.kafka.quotas.minAvailableRatioPerVolume: 0, per-user quotas need kafka.cluster.kafka.authorizer.principalBuilderClass: "", which changes how ACLs and superUsers match principals, and none of these settings take effect on clusters first installed on Hopsworks 4.3 or 4.5.
    • HELM Added airflow.dependencies.mysql.ddlConsulServiceName (default mysqlddl), the DDL MySQL server the Airflow migration Job connects to.
    • HELM Added onlinefs.deployment.strategy to set the rollout strategy of OnlineFS.
    • HELM Added rondb.rondb.rdrs.probes to configure the RonDB REST server probes.

    5.0.12#

    Helm chart 5.0.12 · Released on 2026-09-21 · Changes since 5.0.11 · Python client 5.0.9 (5.0.8, 5.0.9)

    What's changed#

    • API Fixed the Python client installing PyMySQL 1.2.1 or later, with which import hsfs fails with an ImportError; it now requires PyMySQL below 1.2.1.
    • API FRONTEND Added Driver overhead factor and Executor overhead factor to the Spark configuration of jobs, Jupyter and project defaults, which set spark.driver.memoryOverheadFactor and spark.executor.memoryOverheadFactor, also as driver_memory_overhead_factor and executor_memory_overhead_factor of JobConfiguration in the Python client (PySpark jobs). Jupyter Spark sessions now default both to 0.4, as PySpark jobs do, so notebooks and their executors request more memory than before.
    • FRONTEND Added a Monitor button to each running Spark application on the Jupyter page, showing its driver and executor pods, and fixed the Jupyter server monitor showing a Spark executor as the notebook pod; the Grafana link there and in the job drawer menu is now called Metrics.
    • HELM Fixed service logs being dropped from the .services OpenSearch index when Kubernetes labels pushed it past 1000 fields.
    • HELM Changed the memory split of the remote shuffle servers to stop heap out-of-memory crashes: 20% of spark.rss.shuffleServer.resources.limits.memory is reserved for native memory and the rest is split 25% heap, 75% off-heap.
    • HELM Fixed the remote shuffle servers never receiving their off-heap memory setting, which left their buffers about nine times too small.

    Breaking changes#

    • HELM Removed hopsworks.variables.jupyter_spark_driver_memory_overhead_factor, added in 5.0.10; the driver memory overhead of a notebook now comes from its Spark configuration. Remove it from your values before you upgrade, because the values schema rejects it; with --reuse-values, which keeps the old default, use --reset-then-reuse-values.
    • HELM Filebeat now keeps only the Kubernetes labels listed under olk.filebeat.kubernetesMetadata, and the serviceLabelKey of each olk.logstash.extendServicesPipeline entry, on service logs, instead of every pod label. Add any other label you filter on to olk.filebeat.kubernetesMetadata.extraPodLabels, extraNamespaceLabels or extraNodeLabels; an overridden olk.filebeat.logs_locations keeps its own add_kubernetes_metadata processor and every label, so to get the fix set addKubernetesMetadata: true on each entry and drop that processor.

    Upgraded components#

    Component 5.0.11 5.0.12
    Base environment images 5.0.9 5.0.10

    Configuration changes#

    • HELM Changed the default spark.rss.shuffleServer.bufferCapacityRatio to 0.6 and spark.rss.shuffleServer.resources.limits.cpu to 2000m.
    • HELM Removed hopsworks.variables.jupyter_spark_driver_memory_overhead_factor, the driver memory overhead of Jupyter servers in Spark environments, which now comes from the notebook's Spark configuration.
    • HELM Added olk.filebeat.kubernetesMetadata, the pod, namespace and node labels Filebeat keeps on service logs (extraPodLabels, extraNamespaceLabels, extraNodeLabels for your own), and addKubernetesMetadata on each olk.filebeat.logs_locations entry.

    5.0.11#

    Helm chart 5.0.0 · Released on 2026-06-11 · Changes since 4.8.2 · Python client 5.0.0

    What's changed#

    • API FRONTEND Addressed vulnerabilities in the feature store.
    • API FRONTEND Fixed the Hopsworks REST API and UI stalling when many Jupyter, terminal or app sessions are open.
    • API FRONTEND HELM Added Agent Deployments, the Python deployments without a model, listed under Agents and with optional OpenTelemetry tracing into project feature groups, created in the Python client with ModelServing.deploy_agent; see Agent Deployments. Size the tracing sidecar with hopsworks.variables.agent_deployment_otel_cpu and agent_deployment_otel_memory_mb, or turn tracing off for the cluster with agent_deployment_otel_enabled: "false".
    • API FRONTEND HELM Added Apps, Streamlit dashboards and custom web apps such as Flask, FastAPI or Gradio that run as long-lived services in a project, on the new python-app-pipeline environment, also managed in the Python client with Project.get_app_api(); see Apps.
    • API FRONTEND Added SAP HANA, Databricks Unity Catalog (on AWS, with a personal access token or OAuth machine-to-machine credentials), MongoDB and Oracle data sources, which the Python client can also create with FeatureStore.create_data_source; see Data sources.
    • API FRONTEND Added a Users dataset with a private home directory per member, where Jupyter, Git and the web terminal start; a Data Owner can add it to an existing project, and it can't be shared; Project.home_path in the Python client gives your home directory.
    • API FRONTEND Added logical dates and data intervals to job schedules, which jobs read from HOPS_LOGICAL_DATE, HOPS_START_TIME and HOPS_END_TIME, with catch-up of missed intervals, and backfill runs with Job.run(start_time=..., end_time=...) in the Python client; see Schedule a job.
    • API FRONTEND Added account-level environment variables, encrypted and injected into every job, deployment, app, Jupyter server and terminal you start, optionally from one of your secrets or shared with a project, and managed in the Python client with hopsworks.get_env_vars_api(); see Account-level environment variables.
    • API FRONTEND HELM Added the python-agent-pipeline environment, with FastAPI, LangChain, LlamaIndex and OpenTelemetry, for Python agents.
    • API FRONTEND HELM Added public links to Streamlit apps (App.make_public() in the Python client), which open without a Hopsworks login, when hopsworks.variables.streamlit_sharing is true.
    • API FRONTEND HELM Added request metrics to apps: an Envoy sidecar measures requests and latency, shown with CPU, memory and Kubernetes status on the app page and in the new App Metrics Grafana dashboard.
    • API FRONTEND Added the datasets shared with a project to the HopsFS mount of Jupyter, jobs, apps and terminals, under /hopsfs/shared-datasets/<project>/<dataset>.
    • API FRONTEND Added the hops CLI to the Python client package, to work with feature groups, feature views, training datasets, models, deployments, agents, apps, jobs and data sources from a shell, with browser sign-in that creates an API key for the project you pick.
    • API FRONTEND HELM Added an optional transform script to dltHub ingestion jobs (transform_script_path of SinkJobConfiguration in the Python client), which now run in the dlthub-ingestion-pipeline environment; see Ingest data with dltHub.
    • API FRONTEND Added downloading models from Hugging Face into the Model Registry from the UI or with ModelRegistry.hf_download in the Python client; see Import a model from Hugging Face.
    • API FRONTEND Added deleting a feature group together with the feature views that use it (FeatureGroup.delete(delete_feature_views=True) in the Python client), or with force=True while keeping them, and removing a feature group or feature store shared with your project without deleting the original.
    • API Added a choice of a hash or an ordered index for the primary key of online feature groups (primary_key_index_type in OnlineConfig).
    • API Added lookback windows to point-in-time joins (lookback of feature view reads and training data) and extra filters to batch data reads of feature views (extra_filter of get_batch_data) (also in 4.8.10).
    • API FRONTEND HELM Added the vllm-omni serving runtime and a choice of vLLM version for each deployment (vllm_image_tag in the Python client), and moved the vllm-openai runtime to the vllm/vllm-openai image (also in 4.8.7).
    • API Changed inserts into online feature groups to write only the latest row of each primary key, by event time, to the online store, and to skip rows whose TTL has already expired; pass online_ingestion_options={"mark_online_rows": False} to write every row.
    • API Added operation="insert" for DELTA feature groups, which appends the rows without merging them on the primary key, and stopped DELTA inserts from failing on rows with duplicate primary keys and event times.
    • API Added built-in model-dependent transformation functions: log_transform, equal_width_binner, equal_frequency_binner, quantile_binner, top_k_categorical_binner, quantile_transformer, rank_normalizer, winsorize, impute_mean, impute_median, impute_constant, impute_mode and impute_category.
    • API Added support for Great Expectations 1.x, up to 1.17.1, and Polars 1.x, up to 1.40.1, to the Python client.
    • API Added Spark Connect support to the Python client, as used by Spark web terminals; there statistics are computed with pandas and HUDI feature groups can't be read or written.
    • API Added a cache to Model.download() in the Python client, which reuses a downloaded model version across sessions; free it with Model.clear_cache().
    • API Added Project.get_superset_api() to the Python client to manage Superset datasets, charts and dashboards.

    • API Fixed dltHub ingestion jobs created from the Python client failing on source columns whose names the feature store changes, such as names with upper-case letters (also in 4.8.7).
    • API Fixed OnlineFS stopping writes to an online feature group after a single "No such table existed" error, such as right after the table was created; it now retries first.
    • API FRONTEND Fixed Python job logs being lost when the job is stopped, or when the first runs of a job end at the same time.
    • API Fixed Spark writes to partitioned HUDI feature groups created with an older Hudi version failing (also in 4.8.7).

    Breaking changes#

    • API FRONTEND Hopsworks now deletes finished job executions and their logs 90 days after they end, instead of keeping them, and deletes the older ones as soon as it starts after the upgrade. Copy the logs you want to keep before you upgrade; the cluster variable executions_ttl_days sets the retention (0 turns it off) and takes effect when Hopsworks restarts.
    • API Model.save in the Python client now moves model files saved from a path under /mnt/hopsfs into the model registry, instead of uploading a copy and keeping the originals; pass keep_original_files=True to keep them.
    • API In a job with a schedule, read() of a feature group with an event time now reads only the rows of the run's data interval, from HOPS_START_TIME to HOPS_END_TIME, instead of the whole feature group, when it's called without start_time, end_time or wallclock_time. Pass start_time and end_time where a scheduled job must read more; see Schedule a job.
    • API create_feature_group in the Python client now creates a DELTA feature group by default, and fails when the deltalake package is missing, instead of falling back to HUDI; time_travel_format=None now creates a feature group without time travel, instead of choosing the default. Set time_travel_format to "DELTA" or "HUDI" explicitly where you relied on the old behaviour.
    • API The Python client no longer supports Python 3.9; use Python 3.10 to 3.13, see the client installation guide.
    • API The Python client now prefixes its internal functions and methods, those not in the API reference, with an underscore, such as hopsworks_common.client.get_instance(), which is now _get_instance(), so code that calls them fails. Use the documented API instead.
    • API The disable_online_ingestion_count write option of feature group inserts is now read from online_ingestion_options in the Python and Java clients, so a top-level disable_online_ingestion_count is ignored; move it into online_ingestion_options, or in Java rename the key to online_ingestion_options.disable_online_ingestion_count.
    • FRONTEND HELM Upgraded Airflow from 1.10 to Airflow 3, and DAGs written for Airflow 1.10 don't run on it. The upgrade drops and recreates the Airflow metadata database, so DAG run history and the Variables and Connections created in Airflow are lost for good; see Airflow 3 in Hopsworks.
    • HELM 5.0.0's Airflow migration Job connects through the round-robin MySQL service, so on a cluster with more than one RonDB MySQL server the upgrade to Airflow 3 splits the Airflow schema across servers and never completes; upgrade to 5.0.13 or later instead.
    • HELM 5.0.0 supports Kubernetes up to 1.34 only, without the Kubernetes 1.35 and 1.36 support of 4.8.13; if you run 4.8.13 or later on Kubernetes 1.35 or 1.36, upgrade to 5.0.1 or later instead.
    • HELM 5.0.0 doesn't have kserve.kserve.servingruntime.vllmopenai.imageRegistry and kserve.kserve.servingruntime.vllmomni.imageRegistry, which 4.8.13 added, so the values schema rejects them; if you set them, upgrade to 5.0.1 or later instead.
    • HELM 5.0.0 doesn't have hive.externalLoadBalancer, global.unmanagedLoadBalancers.metastore, hopsworks.variables.hopsworks_public_proxy_url, global._hopsworks.wipeDataOnUninstall, certs-operator.gracefulCertTeardown and the cleanupOnUninstall value of the charts, such as hopsworks.cleanupOnUninstall, which 4.8.14 added, so the values schema rejects them; if you set them, upgrade to 5.0.2 or later instead.
    • HELM 5.0.0 doesn't have hopsworks.envs.postInstall.ASADMIN_TIMEOUT_SEC, ASADMIN_DEPLOY_TIMEOUT_SEC and DEPLOY_RETRY_INTERVAL_SEC, which 4.8.17 added, so the values schema rejects them; if you set them, upgrade to 5.0.3 or later instead.
    • HELM 5.0.0 doesn't have docker-registry.affinity, minio.affinity and hopsworks.dockerRegistry.preset.affinity, which 4.8.18 added, so the values schema rejects them; if you set them, upgrade to 5.0.6 or later instead.
    • HELM 5.0.0 doesn't have global._hopsworks.initContainerResources and olk.filebeat.kubernetesMetadata, which 4.8.21 added, so the values schema rejects them; if you set them, upgrade to 5.0.12 or later instead.
    • HELM Removed hopsworks.variables.dlthub_image_name, replaced by the dlthub-ingestion-pipeline environment, and hopsworks.payara.executorService, replaced by hopsworks.payara.websocketProxy. Remove them from your values before you upgrade, because the values schema rejects them.
    • HELM global._hopsworks.superset.mysql.enabled and global._hopsworks.superset.redis.enabled must match superset.mysql.enabled and superset.superset.redis.enabled, which used to be enough on their own. If you disabled the MySQL or Redis of Superset, also set the matching global value to false, or the chart fails to render.
    • HELM The Spark operator pre-upgrade Job now pulls the spark-operator-crds image (spark.sparkOperatorUpgradeJob.crdImage) on every upgrade, instead of the toolbox image (also in 4.8.17). Air-gapped installations must mirror it first, or helm upgrade fails.
    • HELM hopsworks.variables.jupyter_shell_command is now a JSON list of the command and its arguments, instead of a path. If you set it, rewrite it as a list, for example '["/bin/bash"]', because a plain path produces an invalid Jupyter configuration.
    • HELM Removed VLLM_USE_FLASHINFER_SAMPLER=0 from the vLLM serving runtimes (also in 4.8.7). If you serve vLLM models on GPUs older than compute capability 7.5, set it in kserve.kserve.servingruntime.vllmopenai.env or kserve.kserve.servingruntime.vllmomni.env.
    • The base environments now run Python 3.12, NumPy 2, CUDA 13, PyTorch 2.11, scikit-learn 1.8, TensorFlow 2.19 and Ray 2.55, instead of Python 3.11, NumPy 1.26, CUDA 12.8, PyTorch 2.8, scikit-learn 1.3, TensorFlow 2.17 and Ray 2.39, and the upgrade moves them to these versions, so jobs, notebooks and deployments on them can break. Test your code against the new versions before you upgrade; an environment you cloned is not upgraded, so if it fails afterwards, clone the new base environment and reinstall your libraries, see Concerning upgrades.
    • The scikit-learn model server, which serves scikit-learn models deployed without a predictor script, now runs scikit-learn 1.8 instead of 1.3, so a deployment of a model saved with scikit-learn 1.3 can fail to start, as gradient boosting models do, or fail every request, as random forests do. Train such models again with scikit-learn 1.8, for example in the 5.0 base environments, and deploy the new model version (model server).
