# Hopsworks 5.0.0

This page lists the changes since Hopsworks 4.8.
Entries marked with a 4.8 release also shipped in that 4.8 patch release, so you can skip them if you upgrade from it or a later one.
If you run 4.8.13 or later, upgrade to the latest 5.0 release instead of 5.0.0; see the migrations.

## Release notes

- Added `ddl-mysqld`, a separate MySQL server for online feature store schema changes, enabled by default with `rondb.rondb.meta.ddlMySQLd.enabled` (also in 4.8.4).
- Added asynchronous upload of HopsFS blocks to object storage, off by default (`hopsfs.objectStorage.asyncUpload.enabled`).
  When it is on, a stopping DataNode first uploads its pending blocks, which can take about an hour with the defaults of `hopsfs.datanode.gracefulDrain`; turning that drain off can lose blocks not yet uploaded.
- Added `hopsfs.namenode.blockSizeMiB` (default `128`) to set the HopsFS block size.
- Added `DataMemory`, `TimeBetweenGlobalCheckpoints` and other RonDB settings to `rondb.rondb.rondbConfig` (also in 4.8.5).
- Added `hopsworks.variables.kube_user_workload_tolerations` to add tolerations to user workloads such as Jupyter, jobs and deployments (also in 4.8.8).
- Added `hopsworks.dockerImage.packageAuth.secretName` and `hopsworks.dockerImage.packageAuth.caCertsConfigMap` for pip, conda and apt mirrors that need credentials or a private CA (also in 4.8.8).
- Added `onlinefs.configmapOverrides` to tune the threads, caches, and RonDB, Kafka and logging settings of the online feature store service.
- Added `arrowflight.deployment.server.hopsfs_query_mode` to make the ArrowFlight server load feature group data into DuckDB tables (`table`) instead of views (`view`) (also in 4.8.3).
- Added `hopsworks.payara.websocketProxy` to tune the WebSocket proxy of Jupyter, terminals and Python apps, such as `maxSessionsPerApp` (default `500` per pod).
- Added WebSocket proxy panels to the Hopsworks Grafana dashboard, replacing the Jupyter executor pool panel.
- Added an App Metrics Grafana dashboard with the request rate, latency, CPU and memory of Python apps.
- Added Grafana dashboards and Prometheus alerts for the MySQL and Redis of Superset.
- Added a Superset Public role to share dashboards and chart permalinks without a login, and enabled dashboard role-based access control.
  Only dashboards granted to the Public role are public; set `superset.superset.allowAnonymousAccess: false` to require a login for all.
- Added `hopsworks.variables.superset_proxy_max_connections`, `superset_proxy_connect_timeout_ms`, `superset_proxy_read_timeout_ms` and `superset_proxy_connection_request_timeout_ms` for the Hopsworks proxy in front of Superset.
- Added `hopsworks.variables.streamlit_sharing` (default `false`) to allow Streamlit apps that are reachable without a Hopsworks login.
- Added the `python-app-pipeline` environment, with Streamlit, for interactive apps.
- Added the `python-agent-pipeline` environment, with FastAPI, LlamaIndex and OpenTelemetry, for Python agents.
- Added the `agent-job` environment, with Claude Code and OpenAI Codex, for agent jobs.
- Added the `dlthub-ingestion-pipeline` environment for ingesting data into feature groups with dltHub.
- Added `hopsworks.variables.agent_jobs_enabled` (default `"true"`) to turn agent jobs on or off.
- Added an OpenTelemetry tracing sidecar to agent deployments, sized with `hopsworks.variables.agent_deployment_otel_cpu` and `agent_deployment_otel_memory_mb`; turn it off with `hopsworks.variables.agent_deployment_otel_enabled: "false"`.
- Added the `vllm-omni` serving runtime for vLLM-Omni models; the `vllm-openai` runtime now uses the `vllm/vllm-openai` image (also in 4.8.7).
- Added `hopsworks.variables.kube_serving_vllm_versions` and `kube_serving_vllm_omni_versions` (default `v0.20.0`), the vLLM image tags a deployment can choose; set them too when you change the vLLM runtime images (also in 4.8.7).
- Added `hopsworks.variables.platform_intelligence_llm_api_key`, `platform_intelligence_llm_base_url` and `platform_intelligence_llm_model` for the LLM of Platform Intelligence, which stays off without an API key.
- Added `hopsworks.variables.kube_scheduling_jobinit_cpu_requests`, `kube_scheduling_jobinit_cpu_limits`, `kube_scheduling_jobinit_memory_requests_mb` and `kube_scheduling_jobinit_memory_limits_mb` to size the initialization step of Spark and Ray jobs.
- Added Kyverno policy exceptions so Python apps and web terminals start under Kyverno policies (`hw-kyverno.policyExceptions.pythonapp.enabled`, `hw-kyverno.policyExceptions.terminal.enabled`).
- Added `global._hopsworks.kyverno.policies.addCertificatesVolume.initContainers.enabled` to inject the custom CA certificates into the init containers of pods annotated `kyverno-inject-certs-init: enabled` (also in 4.8.8).
- Changed the default HopsFS resources: NameNode and DataNodes get 1024 MiB of heap, a CPU request of 1 and a CPU limit of 4, the NameNode 1024 MiB of direct memory, and DataNodes a memory limit of 2048Mi instead of 750Mi.
  With 5 DataNodes by default, plan for the extra CPU requests; the NameNode memory limit stays 2048Mi, which heap and direct memory now fill.
- Changed the HopsFS DataNode PodDisruptionBudget to evict one DataNode at a time; `hopsfs.datanode.podDisruptionBudget.minAvailable` is ignored.
- Changed HopsFS pods to restart when a `helm upgrade` changes the HopsFS configuration.
- Changed the console logs of the HopsFS NameNode and DataNodes from JSON to plain text.
- Changed RonDB upgrades to roll the management server before the data nodes, so data nodes no longer shut down with error 2305 (also in 4.8.6).
- Changed `helm upgrade` to fail when `rondb.rondb.clusterSize.numNodeGroups` differs from the running cluster, because RonDB can't change node groups online (also in 4.8.6).
- Changed `hopsfs.image.registry`, when set, to override `global._hopsworks.imageRegistry` as the full registry and path prefix of the HopsFS image, ending in `/`.
- Changed the default Python version of the base environments from 3.11 to 3.12 (`hopsworks.variables.docker_base_image_python_version`).
- Changed the default `hopsworks.variables.ray_version` from 2.9.0 to 2.55.1.
- Changed the Redis of Superset to cap its memory at 256 MB with `allkeys-lru` eviction.
- Deprecated `airflow.reset_db_if_error`, which Airflow 3 ignores.
- Upgraded HopsFS to 3.4.3.1-EE-RC0, OnlineFS to 2.3, the Hive Metastore to 3.0.0.14.5-v1, Trino to 480-v6 and the Spark history server to 3.5.5.1.
  The upgrade migrates the Hive Metastore schema in place.
- Upgraded RonDB to 26.02.4 (also in 4.8.11).
- Upgraded the vLLM serving runtimes to v0.20.0 (also in 4.8.7).
- Upgraded TensorFlow to 2.19.0 and the scikit-learn model server to 0.14.1.
- Upgraded Superset to 6.0.0p2.4.
- Upgraded the Payara and OpenSearch 1.3.6.2 images to fix security vulnerabilities.
- Upgraded the Grafana, OpenSearch Dashboards, Strimzi and remote shuffle service images, and the Redis 7.4.9 and MySQL images of Superset, to fix security vulnerabilities (also in 4.8.11).
- Fixed external LoadBalancer Services, such as those of ArrowFlight, HopsFS, OpenSearch and Trino, not being created with Helm 3.20.1 and later when a component leaves its own setting unset.
  These components again fall back to `global._hopsworks.externalLoadBalancers.enabled` and `global._hopsworks.externalLoadBalancers.managed`.
- Fixed members with the Feature store restricted project role getting more access to OpenSearch than intended.
- Fixed `hopsfs.namenode.auditLog.enableStatOperation` and `enableListOperation` being ignored, so the NameNode no longer audit-logs stat and list operations unless you set them to `true` (also in 4.8.8).
- Fixed `helm upgrade --force` failing with a conflict on unchanged chart Jobs, whose names now include the Helm release revision, so `helm upgrade` runs them again every time (also in 4.8.3).
- Fixed the preset base image push Job not running again when only image versions or digests changed, for example with Argo CD (also in 4.8.6).
- Fixed fresh installs failing and rolling back when the Knative Serving webhook was not ready yet.
- Fixed Airflow pods failing to start when the HopsFS mount took longer than 30 seconds.

## Breaking changes

- **Action required:** Upgraded Airflow from 1.10 to Airflow 3, and DAGs written for Airflow 1.10 don't run on it.
  The upgrade drops and recreates the Airflow metadata database, so DAG run history and the Variables and Connections created in Airflow are lost for good; see the migrations below.
- **Action required:** `hopsworks.variables.jupyter_shell_command` is now a JSON list of the command and its arguments.
  If you set it, rewrite it as a list, for example `'["/bin/bash"]'`, because a plain path produces an invalid Jupyter configuration.
- **Action required:** Removed `hopsworks.variables.dlthub_image_name`, replaced by the `dlthub-ingestion-pipeline` environment, and `hopsworks.payara.executorService`, replaced by `hopsworks.payara.websocketProxy`.
  Remove them from your values before you upgrade, because the values schema rejects them.
- **Action required:** `global._hopsworks.superset.mysql.enabled` and `global._hopsworks.superset.redis.enabled` must match `superset.mysql.enabled` and `superset.superset.redis.enabled`.
  If you disabled the MySQL or Redis of Superset, also set the matching global value to `false`, or the chart fails to render.
- **Action required:** The Spark operator pre-upgrade Job now pulls the `spark-operator-crds` image (`spark.sparkOperatorUpgradeJob.crdImage`) on every upgrade (also in 4.8.17).
  Air-gapped installations must mirror it first, or `helm upgrade` fails.
- **Action required:** Removed `VLLM_USE_FLASHINFER_SAMPLER=0` from the vLLM serving runtimes (also in 4.8.7).
  If you serve vLLM models on GPUs older than compute capability 7.5, set it in `kserve.kserve.servingruntime.vllmopenai.env` or `kserve.kserve.servingruntime.vllmomni.env`.

## Migrations

### Before the upgrade

1. Required if you run 4.8.13 or later, or use Airflow with more than one MySQL server: upgrade to the latest 5.0 release instead of 5.0.0.
   5.0.0 doesn't install on Kubernetes 1.35 or 1.36, which 4.8.13 supports; it ships older RonDB and image builds than 4.8.14 and later; and its Airflow migration never completes with more than one MySQL server.
2. Required: back up the cluster as described in [Disaster recovery](https://docs.hopsworks.ai/5.0/setup_installation/admin/ha-dr/dr/), because the upgrade drops the Airflow database and migrates the HopsFS and Hive Metastore schemas, which can't be rolled back.
3. Required: update your values for the breaking changes above.
   To find the removed settings in the values of the current release, run the command below, and also check whether they set `superset.mysql.enabled` or `superset.superset.redis.enabled` to `false`.

    ```sh
    helm get values <release-name> -n <namespace> -o yaml | grep -n -E 'jupyter_shell_command|dlthub_image_name|executorService'
    ```

4. Optional, if you use Airflow: write down the Variables and Connections you created in Airflow, and any DAG run history you need.
5. Optional, if you use Airflow: back up `Projects/<project>/Airflow/` of each project in HopsFS, to keep the Airflow 1.10 versions of your DAG files.

### After the upgrade

1. Required, if you use Airflow: port your Airflow 1.10 DAGs to Airflow 3, and regenerate the DAGs created in the Hopsworks UI, as described in [Airflow 3 in Hopsworks](https://docs.hopsworks.ai/5.0/user_guides/projects/airflow/airflow3_upgrade/).
