# Hopsworks 5.0.9

## Release notes

- Added `global._hopsworks.initContainerResources` (`waiter`, `tool`, `runtime`) to size the requests and limits that init containers now set.
- Changed the base image library sync timeouts (`hopsworks.variables.docker_operations_timeout_listing_minutes`, `docker_operations_timeout_check_minutes`, `docker_operations_timeout_export_minutes`) from 5 to 15 minutes, and `max_concurrent_base_sync_ops` from 6 to 5, so large base images finish syncing.
- Upgraded HopsFS to 3.4.3.1-EE-RC5, Hive to 3.0.0.14.7-v1, Trino to 480.1-v1, the Spark history server to 3.5.5.3 and RonDB to 26.02.9.
- Fixed init containers without requests and limits being charged a namespace `LimitRange` default for the whole life of the pod, which could exhaust node capacity; the RonDB and Consul charts are not covered yet.
- Fixed the chart failing to render with `hopsworks.dropDatabase: true`.
- Fixed the KServe local model controller image (`kserve.kserve.localmodel.enabled`) failing to pull.

## Breaking changes

- **Action required:** Init containers now set CPU and memory requests and limits.
  If a namespace `LimitRange` has a `min` or `max` they don't fit, set `global._hopsworks.initContainerResources` before you upgrade, or Kubernetes rejects the pods.

## Migrations

No migration steps are needed beyond the breaking changes above.
