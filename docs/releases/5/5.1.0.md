# Hopsworks 5.1.0 { #hopsworks-5-1-0 }

This page lists the changes since Hopsworks 5.0.0.
Entries marked with a 5.0 release also shipped in that patch release, which describes them in full, so you can skip them if you upgrade from it or a later one.

## Release notes

- Added an optional persistent BuildKit daemon (`global._hopsworks.buildkitd.enabled`) that keeps caches between environment builds; each replica requests 8 CPUs, 16Gi of memory and a 100Gi volume.
- Added `hopsworks.variables.npm_registry_url` for the npm registry of Python environments.
- Added `hopsworks.variables.docker_operations_lock_dependencies`, `docker_operations_allow_hermetic_custom_commands` and `docker_operations_multi_region_copy`, off by default, for hash-locked build dependencies, cached hermetic custom commands and image copies to the second region.
- Added `hopsworks.dockerImage.pypi.pythonDownloads` (default `never`), so uv never downloads a Python interpreter during environment builds.
- Added the `dbt-pipeline` environment, with dbt and its Trino and DuckDB adapters.
- Added Trino catalogs created by project Data Owners, loaded when an administrator restarts Trino and tested on a single-node coordinator (`global._hopsworks.trino.testCoordinator.enabled`).
- Added file-based credentials, such as Oracle wallets, for user-created Trino catalogs, through a privileged sidecar on every Trino pod that mounts `/apps/mountable-secrets` from HopsFS read-only.
- Added `global._hopsworks.trino.egressProbe.echoUrl` to show which IP addresses an external database must allow.
- Added `spark.sql.ansiEnabled` (default `false`), so Spark 3.5 SQL keeps returning null on overflow and invalid casts.
- Added cluster variables for the default CPU, memory and GPU of new jobs and Python apps, such as `hopsworks.variables.spark_job_executor_memory`.
- Added `hopsworks.variables.pushgateway_group_ttl_minutes`, `pushgateway_monitor_interval_ms` and `pushgateway_cleaner_batch_size` to clean stale Pushgateway metric groups.
- Added `olk.opensearch.audit.enabled` (default `false`) and `olk.opensearch.audit.retentionDays` for OpenSearch security audit logs.
- Added `olk.opensearch.security.default_tenant` (default `Private`), the tenant OpenSearch Dashboards opens in.
- Added `kserve.knative.imageRegistry` for the Knative images.
- Changed every `helm upgrade`, including values-only ones, to rebuild the feature store search index afterwards.
- Changed upgrades to update the KServe, Knative Serving and cert-manager CRDs in a pre-upgrade Job, which removes the unused `predictors.serving.kserve.io` CRD.
- Changed the default `kserve.kserve.controller.deploymentMode` from `Serverless` to `Knative`, its KServe 0.19 name.
- Changed Spark metrics to be scraped by Prometheus instead of pushed to the Pushgateway.
- Changed environment image builds to the `rondb-high-priority` priority class (`hopsworks.variables.docker_operations_buildkit_priority_class`), so they can preempt Jupyter and job pods.
- Changed `hopsworks.variables.docker_operations_buildkit_extra_args` to empty by default, dropping the S3 build cache arguments that failed without S3 credentials; set them again to keep an S3 build cache.
- Changed Grafana to load the Hopsworks dashboards from its image instead of ConfigMaps; add your own with `global._hopsworks.grafana.extraDashboardProviders`.
  A custom Grafana image must contain the Hopsworks dashboards, and a custom `grafana.grafana.dashboardProviders` must point to `/usr/share/grafana/dashboards/<folder>`.
- Changed OpenSearch snapshots and restores to skip the `.opendistro_security` index and hidden plugin indices.
- Changed AlertManager emails to link the alert title to the job, feature group or feature view that raised it.
- Deprecated `kserve.istio.gateways.http10` for `kserve.istio.gateways.ingress.http10`; the old key, ignored in 5.0, works again.
- Fixed model serving requests over HTTPS skipping the model serving authenticator when `kserve.knative.https.enabled` is `true`.
- Fixed image pulls from the in-cluster Docker registry failing with `x509: certificate signed by unknown authority`, for example on RHEL-family nodes.
- Fixed every model deployment failing when the Knative controller started with an empty registry certificate.
- Fixed images built from custom commands keeping the package repository credentials staged for the build; rebuild those images, and rotate the credentials in `hopsworks.dockerImage.packageAuth.secretName`.
- Fixed OpenSearch snapshot restores never finishing on single-node clusters, and indices staying closed after a failed restore.
- Fixed Velero backups leaving out the Trino authentication Secrets, the Velero storage location rejecting AWS S3 without a custom endpoint, and the values schema rejecting a cron string in `hopsworks.velero.backup.schedule`.
- Fixed database migrations crash-looping on a lock left by a transient Kubernetes API error, and restarting once on every fresh install.
- Fixed the Kyverno restricted policies blocking schema fetches of REST, CRM and Google Sheets data sources.
- Fixed the "HDFS Bytes Written" panel of the Spark Grafana dashboard showing bytes read.
- Added support for Kubernetes 1.35 and 1.36, `hive.externalLoadBalancer.enabled`, `hopsworks.velero.backup.storageLocation.s3ForcePathStyle`, an `imageRegistry` for each vLLM serving runtime, `hw-kyverno.policyExceptions.pythonDeployment.enabled`, and variables for RonDB usage, feature monitoring limits, lifecycle webhooks and plain-HTTP registries (also in [5.0.1][hopsworks-5-0-1]).
- Fixed Superset redirects to its internal host, model deployments with images from the managed Docker registry, and the App Metrics dashboard for apps without traffic (also in [5.0.1][hopsworks-5-0-1]).
- Fixed database initialization and migrations starting before the RonDB data nodes had restarted, and failing when a restart outlasted the wait (also in [5.0.1][hopsworks-5-0-1] and [5.0.10][hopsworks-5-0-10]).
- Added Jobs that delete the Secrets, ConfigMaps and certificates `helm uninstall` used to leave behind, and fixed `uv` in the web terminal ignoring `hopsworks.dockerImage.pypi.global_parameters` and failed HopsFS schema migrations being reported as successful (also in [5.0.2][hopsworks-5-0-2]).
- Added `hopsfs.objectStorage.s3.disableCertChecking`, `disableChecksumValidation` and retry settings for the admin sidecar, deprecated `hopsworks.envs.postInstall.DEPLOY_RETRIES`, gave the admin container liveness and startup probes, and fixed the admin pod crash-looping when workers were slow to register (also in [5.0.3][hopsworks-5-0-3]).
- Added `hopsworks.service.worker.external.https.nodePort`, and fixed online feature store ingestion dropping rows on temporary RonDB errors (also in [5.0.4][hopsworks-5-0-4]).
- Added `rondb.rondb.ndbmtdSequencedRollout.enabled` to roll the RonDB data nodes one node group at a time, and raised the MySQL server startup probe to 20 minutes (also in [5.0.5][hopsworks-5-0-5]).
- Added `docker-registry.affinity`, `minio.affinity` and `hopsworks.dockerRegistry.preset.affinity`, and fixed Airflow failing to start on OpenShift (also in [5.0.6][hopsworks-5-0-6]).
- Added `hopsworks.variables.upload_policy` and `hopsworks.jupyter.notebookConfig.enableUploads` to restrict file uploads, and fixed Superset queries through Trino logging `Access Denied` and pod creation stalling when the Vertical Pod Autoscaler is on (also in [5.0.8][hopsworks-5-0-8]).
- Changed the base image library sync timeouts from 5 to 15 minutes and `max_concurrent_base_sync_ops` from 6 to 5, and fixed init containers being charged a namespace `LimitRange` default, the chart failing to render with `hopsworks.dropDatabase: true` and the KServe local model controller image failing to pull (also in [5.0.9][hopsworks-5-0-9]).
- Added the `hopsworks.variables.git_*` variables for private CAs, proxies and TLS verification in Git operations, `jupyter_spark_notebook_server_memory_floor_mb`, the `KafkaAuthenticationFailures` alert and validity settings for the Strimzi CAs, and fixed OnlineFS writes after a table was truncated and Git sign-in with special characters in a token or password (also in [5.0.10][hopsworks-5-0-10]).
- Added `rondb.rondb.mysql.users[].existingSecret`, raised the RonDB data node startup probe from 25 to 240 minutes, made the Kafka Entity Operator follow the placement of the Kafka brokers, and fixed RonDB rolling restarts shutting down healthy data nodes (also in [5.0.11][hopsworks-5-0-11]).
- Added the Spark properties `spark.driver.memoryOverheadFactor` and `spark.executor.memoryOverheadFactor`, changed the memory split and CPU limit of the remote shuffle servers, and fixed their off-heap memory setting and service logs missing from the `.services` index (also in [5.0.12][hopsworks-5-0-12]).
- Added `kafka.cluster.kafka.quotas.type` and `onlinefs.deployment.strategy`, and fixed the Airflow migration Job losing tables with more than one RonDB MySQL server, OnlineFS upgrades stalling on a full node pool and the OpenSearch metrics exporter on satellite deployments (also in [5.0.13][hopsworks-5-0-13]).

## Breaking changes

- Raised the minimum Kubernetes version from 1.27 to 1.34; upgrade Kubernetes first, because Helm refuses to install or upgrade on an older cluster.
- Removed Brewer; remove `global._hopsworks.brewer`, `brewer`, `hopsworks.ingress.brewer`, `hopsworks.variables.brewer_*` and `hw-kyverno.policyExceptions.brewer` from your values, because the values schema rejects them.
- Removed `hopsworks.variables.hive_default_quota` and `hopsworks.variables.enable_conda_install`; remove them from your values, because the values schema rejects them.
- `hopsworks.variables.enable_read_only_git_repositories` now defaults to `false`, so users can commit and push from Git repositories in Hopsworks; to keep them read-only, set it to `'true'` before you upgrade.
- Feature monitoring is now on by default; to keep it off, set `hopsworks.variables.enable_feature_monitoring: 'false'` before you upgrade (also in [5.0.1][hopsworks-5-0-1]).
- The consul-k8s chart fails to render with `disable_hostname` in `consul.consul.server.extraConfig`; remove it, because `consul.consul.global.metrics.disableAgentHostName` (default `true`) replaces it.
- The chart fails to render with `hopsworks.hopsfsMount.enabled: false`, because the new Trino mountable-secrets sidecar needs the HopsFS mount.
  Set `global._hopsworks.trino.mountableSecrets.enabled: false`, and override `trino.trino.initContainers` and `trino.trinotest.initContainers.coordinator` without the `mountable-secrets` container, as `values.openshift.yaml` does.
- `catalog-volume` moved from `trino.trino.configMounts` to the `additionalVolumes` and `additionalVolumeMounts` of `trino.trino.coordinator` and `trino.trino.worker`.
  If you override these lists, copy both entries from the chart's values and remove `catalog-volume` from an overridden `trino.trino.configMounts`, or the Trino pods don't start.
- Prometheus is upgraded from 2.51 to 3.14; check custom alert rules and scrape configs against the [Prometheus 3 migration guide](https://prometheus.io/docs/prometheus/latest/migration/).
- Knative request metrics are now `http_server_request_duration_seconds` instead of `revision_request_count` and `revision_request_latencies`, with new label names, and Spark metrics have new names; update custom Grafana dashboards and alert rules.
- `vpa.image.tag` is now the version of the VPA installer image (default `"1.7.1-2"`), separate from `vpa.imagesTag`; remove any override of it, including the `"1.7.1"` that [5.0.8][hopsworks-5-0-8] asked for.
- Trino pods now run as the `hopsworks-trino` and `hopsworks-trino-test` ServiceAccounts instead of `default`; move anything you attached to `default` for Trino, such as a cloud identity annotation or an OpenShift SCC.
- `helm uninstall` now deletes the data volumes of Consul, the HopsFS DataNodes, Kafka, MinIO, OpenSearch and the remote shuffle service, unless you set `global._hopsworks.wipeDataOnUninstall: false` or label the PVCs `hopsworks.ai/keep=true`; the Superset MySQL volume is deleted regardless (also in [5.0.2][hopsworks-5-0-2]).
- The admin liveness and startup probes now have a default `exec` handler, so a probe you set with `httpGet` or `tcpSocket` also needs `exec: null`, which needs Helm 4 or Helm 3.17.1 or later (also in [5.0.3][hopsworks-5-0-3]).
- Init containers now set CPU and memory requests and limits; if a namespace `LimitRange` has a `min` or `max` they don't fit, set `global._hopsworks.initContainerResources` before you upgrade, or Kubernetes rejects the pods (also in [5.0.9][hopsworks-5-0-9]).
- Filebeat now keeps only the Kubernetes labels listed under `olk.filebeat.kubernetesMetadata`, and the `serviceLabelKey` of each `olk.logstash.extendServicesPipeline` entry, on service logs (also in [5.0.12][hopsworks-5-0-12]).
  Add other labels you filter on to its `extraPodLabels`, `extraNamespaceLabels` or `extraNodeLabels`; if you override `olk.filebeat.logs_locations`, set `addKubernetesMetadata: true` on each entry and drop its `add_kubernetes_metadata` processor.
- Removed `hopsworks.variables.jupyter_spark_driver_memory_overhead_factor`, added in 5.0.10; remove it from your values, because the values schema rejects it (also in [5.0.12][hopsworks-5-0-12]).
- Removed the Kafka quota defaults Job, and `quotas` on a user in `kafka.users` now fail the render under the default `strimzi` quota plugin (also in [5.0.13][hopsworks-5-0-13], which says what to set instead).
- The Airflow migration Job now waits for the DDL MySQL server, so the upgrade hangs with `rondb.rondb.meta.ddlMySQLd.enabled: false`; keep it enabled if you use Airflow (also in [5.0.13][hopsworks-5-0-13]).

## Migrations

### Before the upgrade

1. Required: back up the cluster as described in [Disaster recovery](https://docs.hopsworks.ai/5.0/setup_installation/admin/ha-dr/dr/), because the upgrade migrates the Hive Metastore schema from 3.0 to 4.1 and OpenSearch from 1.3 to 2.19, which can't be rolled back.
2. Required: check that the cluster runs Kubernetes 1.34 or later.

    ```sh
    kubectl version
    ```

3. Required: update your values for the breaking changes above.
   To find the removed settings in the values of the current release, run:

    ```sh
    helm get values <release-name> -n <namespace> -o yaml | grep -n -E 'brewer|hive_default_quota|enable_conda_install|jupyter_spark_driver_memory_overhead_factor|disable_hostname'
    ```

4. Required if you upgrade with `--reuse-values`: use `--reset-then-reuse-values` instead, because `--reuse-values` keeps the defaults of the 5.0 chart, such as `brewer`, which the values schema rejects.
5. Required: check that `hopsworks.variables.admin_email` and `hopsworks.variables.admin_password` in your values, or their defaults if unset, sign in to the Hopsworks admin account.
   The post-upgrade search index rebuild signs in with them and fails the `helm upgrade` when it can't, and its retries can lock the account; if password login is disabled, upgrade to [5.1.1][hopsworks-5-1-1] instead.
6. Required: set `olk.opensearch.knn.circuit_breaker.triggered: false` and `olk.opensearch.knn.circuit_breaker.percent: 75`, or upgrade to [5.1.1][hopsworks-5-1-1] instead, where these are the defaults.
   With the 5.1.0 defaults, OpenSearch drops unflushed vectors and rejects vector writes for about two minutes on its first start on 5.1; inserting the rows again restores lost vectors.
7. Required if a release before 5.0.13 ran with `kafka.cluster.kafka.quotas.defaults.enabled: true`: check for the leftover client-id default quota, as described in [5.0.13][hopsworks-5-0-13].
8. Required if you upgrade from a release before 5.0.13 and Airflow or its migration Job failed after an earlier upgrade on a cluster with more than one MySQL server: drop the `airflow` database on every MySQL server, which can't be undone.
9. Optional, if you upgrade from 5.0.13: upgrade to [5.1.1][hopsworks-5-1-1] instead, because 5.1.0 ships an older RonDB chart without `rondb.rondb.rdrs.probes`, so the RonDB REST server restarts again during a data node failure.

### After the upgrade

1. Optional: check that OpenSearch runs 2.19 and is healthy, as in step 2 of [Upgrading OpenSearch](https://docs.hopsworks.ai/5.2/setup_installation/admin/upgrade_opensearch/#upgrade-steps).

2. Optional, if you manage the Trino authentication Secrets yourself (`trino.auth.createSecrets: false`) and use Velero: label them so backups include them.

    ```sh
    kubectl label secret -n <namespace> trino-admin-credentials trino-monitoring-credentials trino-password-file trino-groups-file backup.hops.works/include=true
    ```
