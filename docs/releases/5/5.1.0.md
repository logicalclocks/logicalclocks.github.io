# Hopsworks 5.1.0

This page lists the changes since Hopsworks 5.0.0.
Entries marked with a 5.0 release also shipped in that 5.0 patch release, so you can skip them if you upgrade from it or a later one.

## Release notes

- Added support for Kubernetes 1.35 and 1.36 (also in 5.0.1).
- Added an optional persistent BuildKit daemon for environment image builds, which keeps base images and package caches between builds.
  Enable it with `global._hopsworks.buildkitd.enabled`; each replica requests 8 CPUs, 16Gi of memory and a 100Gi volume by default.
- Added `hopsworks.variables.npm_registry_url` to set the npm registry of Python environments.
- Added `hopsworks.variables.docker_operations_lock_dependencies`, `docker_operations_allow_hermetic_custom_commands` and `docker_operations_multi_region_copy` (default `"false"`) to lock build dependencies by hash, reuse the layer cache of hermetic custom commands, and copy built images to the second region.
- Added `hopsworks.dockerImage.pypi.pythonDownloads` (default `never`), so uv never downloads a Python interpreter during environment builds.
- Added the `dbt-pipeline` environment: `python-feature-pipeline` with dbt and its Trino and DuckDB adapters.
- Added Trino catalogs that project Data Owners create themselves, loaded when an administrator restarts Trino.
  A single-node Trino coordinator tests their connections; skip it with `global._hopsworks.trino.testCoordinator.enabled: false`.
- Added file-based credentials, such as Oracle wallets, for user-created Trino catalogs, through a privileged sidecar on every Trino pod that mounts `/apps/mountable-secrets` from HopsFS read-only.
- Added `global._hopsworks.trino.egressProbe.echoUrl` so the Trino catalog dialog can show which IP addresses an external database must allow.
- Added `spark.sql.ansiEnabled` (default `false`), so SQL written for Spark 3.5 keeps returning null on overflow and invalid casts on Spark 4.
- Added cluster variables for the default CPU, memory and GPU of new jobs and Python apps, such as `hopsworks.variables.spark_job_executor_memory`; the defaults are unchanged.
- Added `hopsworks.variables.pushgateway_group_ttl_minutes`, `pushgateway_monitor_interval_ms` and `pushgateway_cleaner_batch_size` to clean stale metric groups from the Prometheus Pushgateway.
- Added `olk.opensearch.audit.enabled` (default `false`) for OpenSearch security audit logs, kept for `olk.opensearch.audit.retentionDays` days.
- Added `olk.opensearch.security.default_tenant` (default `Private`), the tenant OpenSearch Dashboards opens in.
- Added `kserve.knative.imageRegistry` to pull the Knative images from their own registry path.
- Added Jobs that delete the Secrets, ConfigMaps and certificates that `helm uninstall` used to leave behind (also in 5.0.2).
- Added `hive.externalLoadBalancer.enabled` to expose the Hive Metastore outside Kubernetes (also in 5.0.1).
- Added `hopsworks.velero.backup.storageLocation.s3ForcePathStyle` for S3-compatible backup stores (also in 5.0.1).
- Added `kserve.kserve.servingruntime.vllmopenai.imageRegistry` and `kserve.kserve.servingruntime.vllmomni.imageRegistry` to pull the vLLM images from a mirror (also in 5.0.1).
- Added `hw-kyverno.policyExceptions.pythonDeployment.enabled` so Python deployments that mount HopsFS can start under the Kyverno restricted policies (also in 5.0.1).
- Added `hopsworks.variables.rondb_usage_cache_ttl_seconds` and `rondb_usage_query_timeout_seconds` for the RonDB usage on the project quotas page (also in 5.0.1).
- Added `hopsworks.variables.feature_monitoring_max_num_features` (default `15`) to cap the features of a feature monitoring configuration (also in 5.0.1).
- Added `hopsworks.variables.lifecycle_webhook_url`, `lifecycle_webhook_cluster_id` and `lifecycle_webhook_secret` to post user, project and membership events to a webhook (also in 5.0.1).
- Added `hopsworks.variables.docker_operations_registry_http` for self-managed registries that serve plain HTTP (also in 5.0.1).
- Added `hopsfs.objectStorage.s3.disableCertChecking` and `hopsfs.objectStorage.s3.disableChecksumValidation` for the HopsFS S3 endpoint (also in 5.0.3).
- Added `hopsworks.envs.postInstall.DEPLOY_RETRY_INTERVAL_SEC`, `ASADMIN_TIMEOUT_SEC` and `ASADMIN_DEPLOY_TIMEOUT_SEC` to tune how the admin sidecar retries the Hopsworks deployment (also in 5.0.3).
- Added `hopsworks.service.worker.external.https.nodePort` to pin the node port of the Hopsworks HTTPS service (also in 5.0.4).
- Added `docker-registry.affinity`, `minio.affinity` and `hopsworks.dockerRegistry.preset.affinity` (also in 5.0.6).
- Added `hopsworks.variables.upload_policy` and `hopsworks.jupyter.notebookConfig.enableUploads` to restrict file uploads (also in 5.0.8).
- Added `hopsworks.variables.git_custom_ca_configmap`, per-provider proxy variables and `git_disable_tls_verification` for Git operations; the CA ConfigMap must exist in every project namespace (also in 5.0.10).
- Added `hopsworks.variables.jupyter_spark_notebook_server_memory_floor_mb` (default `512`) to size the Jupyter server of Spark environments (also in 5.0.10).
- Added the `KafkaAuthenticationFailures` Prometheus alert, and `kafka.cluster.clusterCa.validityDays` and `kafka.cluster.clientsCa.validityDays` for the Strimzi certificates (also in 5.0.10).
- Added `rondb.rondb.mysql.users[].existingSecret` to read the password of a MySQL user from your own Secret (also in 5.0.11).
- Added `kafka.cluster.kafka.quotas.type` to choose the Kafka quota plugin, `strimzi` (the default) or `kafka` for per-user quotas (also in 5.0.13).
- Added `onlinefs.deployment.strategy` to set the rollout strategy of OnlineFS (also in 5.0.13).
- Changed every `helm upgrade`, including values-only ones, to rebuild the feature store search index afterwards (`post-upgrade-opensearch-reindex-job`).
- Changed upgrades to update the KServe, Knative Serving and cert-manager CRDs in a pre-upgrade Job, which removes the unused `predictors.serving.kserve.io` CRD.
- Changed the default of `kserve.kserve.controller.deploymentMode` from `Serverless` to `Knative`, the KServe 0.19 name for the same mode.
- Changed Spark driver and executor metrics to be scraped by Prometheus instead of pushed to the Prometheus Pushgateway.
- Changed environment image build Jobs to use the `rondb-high-priority` priority class (`hopsworks.variables.docker_operations_buildkit_priority_class`), so they can preempt Jupyter and job pods.
- Changed `hopsworks.variables.docker_operations_buildkit_extra_args` to empty by default, dropping the S3 build cache arguments, which failed without S3 credentials; set the old value again to keep an S3 build cache.
- Changed Grafana to load the Hopsworks dashboards from its image instead of ConfigMaps; add your own with `global._hopsworks.grafana.extraDashboardProviders`.
  A custom Grafana image must contain the Hopsworks dashboards, and a custom `grafana.grafana.dashboardProviders` must point to `/usr/share/grafana/dashboards/<folder>`.
- Changed OpenSearch snapshots and restores to skip the `.opendistro_security` index and hidden plugin indices by default.
- Changed AlertManager emails to link the alert title to the job, feature group or feature view that raised it.
- Changed the Hopsworks admin container to have liveness and startup probes (also in 5.0.3).
- Changed the base image library sync timeouts from 5 to 15 minutes (also in 5.0.9).
- Changed the RonDB data node startup probe from 25 to 240 minutes, now set with `rondb.rondb.timeoutsMinutes.ndbmtdStartupProbe` (also in 5.0.11; 5.0.5 to 5.0.10 used 120).
- Changed the Kafka Entity Operator, when enabled with `kafka.cluster.entityOperator`, to follow the tolerations, topology spread and node affinity of the Kafka brokers (also in 5.0.11).
- Changed the memory split of the remote shuffle servers to stop heap out-of-memory crashes, and doubled their CPU limit to `2000m` (also in 5.0.12).
- Deprecated `kserve.istio.gateways.http10` in favor of `kserve.istio.gateways.ingress.http10`; the old key had no effect in 5.0 and now works again, so `true` makes the ingress gateway accept HTTP/1.0.
- Deprecated `hopsworks.envs.postInstall.DEPLOY_RETRIES`, which no longer has an effect (also in 5.0.3).
- Upgraded Spark from 3.5.5 to 4.1.3, the Hive Metastore from 3.0.0 to 4.1.0, the Spark operator to 2.5.1 and the Hudi bundle of the Hive Metastore from 0.12.3 to 1.2.0.
- Upgraded OpenSearch and OpenSearch Dashboards from 1.3.6 to 2.19.6.

- Upgraded HopsFS to 3.4.3.3-EE-RC0 and OnlineFS to 2.4.

- Upgraded Superset to 6.0.0p4.4 and its Redis to 7.4.11.

- Upgraded the Docker registry from 2.8.3 to 3.1.1, and Strimzi to 0.45.2 with Kafka 3.9.2.
- Upgraded Logstash to 7.17.29, Filebeat to 8.19.21 and the scikit-learn model server to 0.19.1.

## Breaking changes

- **Action required:** Raised the minimum Kubernetes version from 1.27 to 1.34, so this release supports Kubernetes 1.34 to 1.36.
  Helm refuses to install or upgrade on an older cluster, so upgrade Kubernetes first.
- **Action required:** Removed Brewer.
  Remove `global._hopsworks.brewer`, `brewer`, `hopsworks.ingress.brewer`, `hopsworks.variables.brewer_*` and `hw-kyverno.policyExceptions.brewer` from your values before you upgrade, because the values schema rejects them.
- **Action required:** Removed `hopsworks.variables.hive_default_quota` and `hopsworks.variables.enable_conda_install`.
  Remove them from your values before you upgrade, because the values schema rejects them.
- **Action required:** `hopsworks.variables.enable_read_only_git_repositories` now defaults to `false`, so users can commit and push from Git repositories in Hopsworks.
  To keep them read-only, set it to `'true'` before you upgrade, because the upgrade writes the value to the cluster.
- **Action required:** Feature monitoring is now on by default, and the upgrade writes `hopsworks.variables.enable_feature_monitoring` to the cluster (also in 5.0.1).
  To keep it off, set it to `'false'` before you upgrade.
- **Action required:** The consul-k8s chart now fails to render with `disable_hostname` in `consul.consul.server.extraConfig`.
  Remove it; `consul.consul.global.metrics.disableAgentHostName` (default `true`) replaces it.
- **Action required:** The chart fails to render with `hopsworks.hopsfsMount.enabled: false`, because the new Trino mountable-secrets sidecar needs the HopsFS mount.
  Set `global._hopsworks.trino.mountableSecrets.enabled: false` and override `trino.trino.initContainers` and `trino.trinotest.initContainers.coordinator` without the `mountable-secrets` container, as `values.openshift.yaml` does.
- **Action required:** `catalog-volume` moved from `trino.trino.configMounts` to `trino.trino.coordinator.additionalVolumes`, `trino.trino.worker.additionalVolumes` and their `additionalVolumeMounts`, next to the new `mountable-secrets`.
  If you override these lists, copy both entries from the chart's values, and remove `catalog-volume` from an overridden `trino.trino.configMounts`, or the Trino pods don't start.
- **Action required:** Knative request metrics are now `http_server_request_duration_seconds` instead of `revision_request_count` and `revision_request_latencies`, with new label names, and Spark metrics come from the Spark Prometheus servlet under new names.
  Update custom Grafana dashboards and alert rules that use the old names.
- **Action required:** `vpa.image.tag` is now a string and the installer version (default `"1.7.1-2"`), separate from `vpa.imagesTag`, so an unquoted override fails the values schema; remove the override (also in 5.0.8).
- **Action required:** Trino pods now run as the `hopsworks-trino` and `hopsworks-trino-test` ServiceAccounts instead of `default`.
  Move anything you attached to `default` for Trino, such as a cloud identity annotation or an OpenShift SCC, or connectors lose credentials and pods are refused.
- **Action required:** `helm uninstall` now deletes the data volumes of Consul, the HopsFS DataNodes, Kafka, MinIO, OpenSearch and the remote shuffle service (also in 5.0.2).
  To keep them, set `global._hopsworks.wipeDataOnUninstall: false` or label the PVCs `hopsworks.ai/keep=true`; the Superset MySQL volume is deleted regardless.
- **Action required:** The admin liveness and startup probes now have a default `exec` handler, so a probe you set with `httpGet` or `tcpSocket` also needs `exec: null` (also in 5.0.3).
  This needs Helm 4 or Helm 3.17.1 or later, because older Helm 3 releases ignore a `null` for a subchart value.
- **Action required:** Filebeat now keeps only the Kubernetes labels listed under `olk.filebeat.kubernetesMetadata` on service logs (also in 5.0.12).
  Add any other label you filter on to `olk.filebeat.kubernetesMetadata.extraPodLabels`, `extraNamespaceLabels` or `extraNodeLabels`.
- **Action required:** Removed `hopsworks.variables.jupyter_spark_driver_memory_overhead_factor`, added in 5.0.10 (also in 5.0.12).
  Remove it from your values, because the values schema rejects it.
- **Action required:** Removed the Kafka quota defaults Job, and `quotas` on a user in `kafka.users` now fail the render under the default `strimzi` quota plugin (also in 5.0.13).
  See [5.0.13][hopsworks-5013] for what to set instead.
- **Action required:** The Airflow migration Job now waits for the DDL MySQL server, so the upgrade hangs with `rondb.rondb.meta.ddlMySQLd.enabled: false`; keep it enabled if you use Airflow (also in 5.0.13).

## Migrations

### Before the upgrade

1. Required: back up the cluster as described in [Disaster recovery](https://docs.hopsworks.ai/5.0/setup_installation/admin/ha-dr/dr/), because the upgrade migrates the Hive Metastore schema from 3.0 to 4.1 and OpenSearch from 1.3 to 2.19, which can't be rolled back.
2. Required: check that the cluster runs Kubernetes 1.34 or later.

    ```sh
    kubectl version
    ```

3. Required: update your values for the breaking changes above.
   To find the removed settings in the values of the current release, run:

    ```sh
    helm get values <release-name> -n <namespace> -o yaml | grep -n -E 'brewer|hive_default_quota|enable_conda_install|jupyter_spark_driver_memory_overhead_factor|disable_hostname'
    ```

4. Required: check that `hopsworks.variables.admin_email` and `hopsworks.variables.admin_password` in your values, or their defaults if unset, sign in to the Hopsworks admin account.
   The post-upgrade rebuild of the search index signs in with them, fails the `helm upgrade` when it can't, and its retries can lock the account.
   If password login is disabled, upgrade to [5.1.1][hopsworks-511] instead, which signs in as the agent user.
5. Required: set `olk.opensearch.knn.circuit_breaker.triggered: false` and `olk.opensearch.knn.circuit_breaker.percent: 75`, or upgrade to [5.1.1][hopsworks-511] instead, where these are the defaults.
   With the 5.1.0 defaults, OpenSearch drops unflushed vectors and rejects vector writes for about two minutes on its first start on 5.1; inserting the rows again restores lost vectors.
6. Required if a release before 5.0.13 ran with `kafka.cluster.kafka.quotas.defaults.enabled: true`: check for the leftover client-id default quota, as described in [5.0.13][hopsworks-5013].
7. Required if you upgrade from a release before 5.0.13 and the Airflow migration Job of an earlier upgrade never completed on a cluster with more than one MySQL server: drop the `airflow` database on every MySQL server, which can't be undone.
8. Optional, if you upgrade from 5.0.13: upgrade to [5.1.1][hopsworks-511] instead, because 5.1.0 ships an older RonDB chart without `rondb.rondb.rdrs.probes`, so the RonDB REST server restarts again during a data node failure.

### After the upgrade

1. Optional: check that OpenSearch runs 2.19 and that its health is green, or yellow on a single node.

    ```sh
    kubectl exec -n <namespace> opensearch-0 -c opensearch -- bash -c 'curl -sk -u "admin:$ADMIN_PASSWORD" https://localhost:9200 | grep number'
    kubectl exec -n <namespace> opensearch-0 -c opensearch -- bash -c 'curl -sk -u "admin:$ADMIN_PASSWORD" https://localhost:9200/_cluster/health?pretty | grep status'
    ```

2. Optional, if you manage the Trino authentication Secrets yourself (`trino.auth.createSecrets: false`) and use Velero: label them so backups include them.

    ```sh
    kubectl label secret -n <namespace> trino-admin-credentials trino-monitoring-credentials trino-password-file trino-groups-file backup.hops.works/include=true
    ```
