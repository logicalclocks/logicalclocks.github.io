# Hopsworks 5.0.8

There is no 5.0.7 release of the Helm chart, so this page lists the changes since 5.0.6.

## Release notes

- Added `hopsworks.variables.upload_policy` (`enabled`, `admins_only` or `disabled`) to control who can upload files, from the web UI and from clients such as the Python SDK.
  The upgrade writes the value to the cluster, so a change made in the admin UI lasts until the next upgrade.
- Added `hopsworks.jupyter.notebookConfig.enableUploads`; set it to `false` to block file uploads from the Jupyter UI and base64 uploads through the Jupyter Contents API.
- Changed `hopsworks.variables.spark_version` to 3.5.5.2, the Spark version of the base images.
- Upgraded HopsFS to 3.4.3.1-EE-RC4, Hive to 3.0.0.14.6-v1, the Spark history server to 3.5.5.2 and OnlineFS to 2.3.4.
- Upgraded the MySQL database of Superset to 8.4.11.
- Upgraded the Payara, Filebeat, Grafana, OpenSearch, OpenSearch Dashboards, Logstash, remote shuffle service and Superset images to fix security vulnerabilities.
- Upgraded the Vertical Pod Autoscaler (`global._hopsworks.vpaEnabled`) to 1.7.1, which no longer stalls pod creation for about 20 seconds on clusters with many API groups.
- Fixed Superset queries through Trino logging `Access Denied: Cannot access catalog system`.

## Breaking changes

- **Action required:** `vpa.image.tag` is now a string, so an override such as `1.2` fails the values schema.
  If you override it, quote it and set it equal to `vpa.imagesTag` before you upgrade; with `--reuse-values` and `global._hopsworks.vpaEnabled: true`, use `--reset-then-reuse-values`.

## Migrations

No migration steps are needed beyond the breaking changes above.
