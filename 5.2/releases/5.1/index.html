    Release notes#

    The releases of Hopsworks 5.1, newest first.

    5.1.2#

    Helm chart 5.1.2 · Released on 2026-10-16 · Changes since 5.1.1 · Python client 5.1.2

    What's changed#

    • API FRONTEND HELM Fixed every OpenSearch restart deleting the OpenSearch roles of restricted-access grants and feature group shares. Grants and shares made before the last OpenSearch restart on 5.1.0 or 5.1.1 lost their roles, and granting or sharing again is refused: revoke and grant again, or unshare and share again.
    • API Fixed external Spark clients failing to read, write or delete DELTA feature groups when the HopsFS NameNode and DataNode load balancers are turned off.
    • API Fixed the Python client installing pyarrow 26 next to NumPy 1, with which importing hsfs.feature_group fails with pyarrow requires NumPy 2.0 or newer; it now requires pyarrow below 26.
    • FRONTEND Fixed queued service operations failing on every retry when they removed a user from Superset or set up a project Observer's online feature store connection in Superset, and stopping for good after 68 failed attempts; a failing operation now retries once a day.
    • FRONTEND Changed the SQL Runner of the Query Engine page to fill the page, show row numbers and column types in the results, list a table's columns in the Explorer and draw EXPLAIN (FORMAT GRAPHVIZ) plans as a graph (SQL Runner).
    • FRONTEND Fixed the SQL Runner leaving a query running when you leave it right after starting the query, and its autocompletion offering no column names in WHERE, GROUP BY or join conditions.
    • HELM Addressed vulnerabilities in OpenSearch. It applies once an OpenSearch pod logs Security configuration applied after the upgrade; if none does, run run_security_admin.sh as Security configuration shows.
    • HELM Added an opt-in Job that copies the OpenSearch indices created before OpenSearch 2.0 during a 5.1 upgrade, in a window you pick, so the upgrade to 5.2.1 or later has nothing left to copy; set olk.opensearch.indexUpgrade.mode to report to list them, or to copy (copying on 5.1.x). Turn vector ingestion off in an upgrade of its own first (onlinefs.deployment.vectordb.enabled: false), and pass the mode with --set, not in your values file, because 5.2.1 and later read the same key.
    • HELM Fixed every helm upgrade restarting OpenSearch.
    • Addressed vulnerabilities in the Payara, Hopsworks certificate authority, Grafana, Filebeat and Superset images, and in the MySQL and Redis of Superset.

    Breaking changes#

    • FRONTEND HELM Recorded Trino queries now lose their query text, plan and JSON details after hopsworks.variables.trino_events_strip_details_after_days (7), instead of keeping them until the query is deleted after 61 days, and the first nightly cleanup after the upgrade strips every older one; set it to 61 or more to keep them.
    • FRONTEND HELM The chart no longer enables Trino's MySQL event listener, which crash-looped the Trino coordinator after a RonDB MySQL server restart, so the admin Trino query history records no new queries; to keep it, add the listener as Trino query history shows.
    • HELM If your values restate trino.trino.additionalConfigProperties with its event-listener.config-files entry, which the 5.1.1 chart set by default, remove that entry or add the listener files as Trino query history shows, or Trino doesn't start.

    Configuration changes#

    • HELM Removed the MySQL event listener from the default trino.trino.additionalConfigProperties and from trino.trino.coordinator.additionalConfigFiles and trino.trino.worker.additionalConfigFiles.
    • HELM Changed the default of hopsworks.variables.trino_events_cleaner_batch_size from 1000 to 100.
    • HELM Added hopsworks.variables.trino_events_strip_details_after_days (default 7), the days after which a recorded Trino query loses its text, plan and JSON details.
    • HELM Added olk.opensearch.indexUpgrade.mode (default none), which runs the 5.2 upgrade's OpenSearch index pass in a post-upgrade Job of a 5.1 upgrade, and olk.opensearch.indexUpgrade.activeDeadlineSeconds (default 3600), the deadline of that Job (values).

    The release notes of hopsworks-api 5.1.2.

    5.1.1#

    Helm chart 5.1.1 · Released on 2026-10-09 · Changes since 5.1.0 · Python client 5.1.1

    What's changed#

    • API Fixed find_neighbors in the Python client failing with Engine [NMSLIB] does not support filters on embedding feature groups created before 5.1, and failing on a project's default embedding index when fewer rows than k match.
    • API FRONTEND Fixed Trino giving a project access to only one of several feature stores shared with it.
    • API FRONTEND Fixed a killed Spark job with pending executors staying in the aggregating logs state for up to 20 minutes.
    • FRONTEND HELM Fixed the post-upgrade search index rebuild failing without the admin password, for example when password login is disabled, and running on every upgrade; it now runs in the background once per index format, and shows its progress and a Reindex now button under Cluster settings > Service Operations > OpenSearch Index Commands. The first upgrade to 5.1.1 rebuilds the index, and search is incomplete until it finishes.
    • FRONTEND Fixed the Why? button of an online ingestion in a feature group's activity opening every OnlineFS log of the project instead of that ingestion's; it is now named Logs.
    • HELM Fixed the database migration of the upgrade from 5.0 failing when the feature groups have more than about 32,000 features in total.
    • HELM Fixed OpenSearch losing unflushed vectors and rejecting vector writes for about two minutes on its first start on 5.1. A values file that sets olk.opensearch.knn.circuit_breaker.triggered: true, or an upgrade with --reuse-values, keeps the problem.
    • HELM Fixed RonDB daemons ignoring SIGTERM, so every pod stop ended in a kill and a stopped data node could stall the cluster.
    • HELM Changed the RonDB REST server probes to outlast a data node failure and to use their own port.
    • HELM Fixed the RonDB REST server reading request bodies over 64 KiB as empty; it now buffers them in rondb.rondb.rdrs.uploadPath.
    • HELM Fixed environment builds never starting when rondb.rondb.priorityClass is renamed.

    Breaking changes#

    • API FRONTEND Because of a security fix, Data Scientists ask the creator of a job or a Data Owner of the project to change it, other than its schedule.
    • HELM The post-upgrade search index rebuild signs in as the agent user, instead of with hopsworks.variables.admin_email and admin_password, and fails the helm upgrade if hopsworks.agent_email and hopsworks.agent_password (default agent@hops.io, admin) don't match that account. Set them, or turn the rebuild off with hopsworks.opensearchReindex.enabled: false.
    • HELM The RonDB REST server now uses a probe port and an upload path that need RonDB 26.02.11, where 5.1.0 probed its REST port and set no upload path. If you pin rondb.rondb.images.rondb.tag to an older version, set rondb.rondb.rdrs.probePort.enabled: false and rondb.rondb.rdrs.uploadPath: "", or the REST server doesn't start.

    Upgraded components#

    Component 5.1.0 5.1.1
    Base environment images 5.1.0 5.1.1
    RonDB 26.02.10 26.02.11
    Trino 480-v10 480-v11

    Configuration changes#

    • HELM Changed the default of olk.opensearch.knn.circuit_breaker.triggered from true to false and of olk.opensearch.knn.circuit_breaker.percent from 0.75 to 75.
    • HELM Changed the default of hopsworks.variables.docker_operations_buildkit_priority_class from rondb-high-priority to empty, so environment builds run at the default priority.
    • HELM Changed rondb.rondb.terminationGracePeriodSeconds to one value per component, and the data nodes' default from 60 to 300 seconds; an integer still sets only the data nodes.
    • HELM Fixed values.openshift.yaml for the OpenShift restricted-v2 SCC, covering Strimzi, Kafka, ZooKeeper, the Spark operator and the MySQL and Redis of Superset, and turned off the Prometheus node exporter, which OpenShift ships itself. Use it with Helm 4 or Helm 3.17.1 or later, because older Helm 3 releases ignore its null overrides of subchart values.
    • HELM Fixed the values schema rejecting hopsworks.variables.loadbalancer_external_domain_namenode and hopsworks.variables.loadbalancer_external_domain_datanode.
    • HELM Added hopsworks.opensearchReindex.enabled to turn off the post-upgrade search index rebuild, and hopsworks.variables.command_search_fs_reindex_queue_wait_as_ms to bound its wait for the search command queue.
    • HELM Added rondb.rondb.rdrs.probes and rondb.rondb.rdrs.probePort, the settings and the port of the RonDB REST server probes, and rondb.rondb.rdrs.maxKeepaliveRequests to close a keep-alive connection after that many requests, so clients rebalance after a rolling restart.
    • HELM Added nodePort values to pin the node ports of unmanaged external load balancers: ArrowFlight, OpenSearch, the HopsFS NameNode and DataNodes, Trino, the Hive Metastore, Kafka (bootstrapNodePort, startingNodePort) and the RonDB MySQL and REST servers. The RonDB ones ignore global._hopsworks.externalLoadBalancers.managed and apply only when rondb.rondb.meta.mysqld.externalLoadBalancer.managed or rondb.rondb.meta.rdrs.externalLoadBalancer.managed is false.
    • HELM Added rondb.rondb.rdrs.ttlPurge.enable and activeWindow to turn off the TTL purge of the RonDB REST server or limit it to a daily window.

    Python client#

    The release notes of hopsworks-api 5.1.1.

    5.1.0#

    Helm chart 5.1.0 · Released on 2026-09-24 · Changes since 5.0.0 · Python client 5.1.0

    What's changed#

    • API FRONTEND Addressed vulnerabilities in feature views (also in 5.0.8).
    • API FRONTEND Addressed vulnerabilities in project datasets (also in 5.0.10).
    • API Addressed vulnerabilities in model serving.
    • API HELM Fixed online feature store ingestion skipping rows that failed with transient RonDB errors, such as Rowid already allocated, during a RonDB upgrade; it now pauses and retries every onlinefs.configmapOverrides.onlinefssite.service.pauseRetrySleepMs until they are written (also in 5.0.4).
    • API Fixed online feature store ingestion stalling for every project when a write exceeded the project's RonDB transaction size quota; OnlineFS now commits such a batch in smaller transactions.
    • API Fixed online feature store ingestion stalling after a feature group with pending records was deleted (also in 5.0.2).
    • API FRONTEND Fixed Spark jobs failing to reach the remote shuffle service when an evicted coordinator pod was left behind.
    • API Fixed the Python client installing PyMySQL 1.2.1 or later, with which import hsfs fails with an ImportError; it now requires PyMySQL below 1.2.1 (also in 5.0.12).
    • API Fixed writes to an online feature group failing after its table was truncated (also in 5.0.10).
    • API FRONTEND Added Apache Iceberg as a feature group table format (time_travel_format="ICEBERG"), also for feature groups created from Iceberg tables in a data source (table format).
    • API FRONTEND Added partition transforms (partitioned_by) for Iceberg and Hudi feature groups, Delta liquid clustering (clustered_by), Hudi bucket indexes (bucket_index), z-ordering (zorder_by) and Iceberg sort orders (sort_order) (partitioning).
    • API FRONTEND HELM Added model monitoring, which compares the inference data a deployment logs with the model's training dataset and shows the drift on the deployment page, and distribution comparison to feature monitoring, set up in the Python client with create_model_monitoring of a feature view, model or deployment and compare_on_distribution; hopsworks.variables.feature_monitoring_max_num_features (default 15) caps the features of a configuration (also in 5.0.1).
    • API FRONTEND HELM Added Trino catalogs that project Data Owners create by hand or from a data source; Trino loads them at its daily scheduled restart (02:00 by default, only when a change is pending) or when an administrator restarts it, and tests them on a single-node coordinator (global._hopsworks.trino.testCoordinator.enabled); the Python client manages them with project.get_trino_catalog_api() and creates one from a data source with create_trino_catalog() of its storage_connector (Trino catalogs).
    • API FRONTEND Added dltHub ingestion jobs that copy several tables of a data source, each into its own feature group with its own settings and resources (dltHub ingestion).
    • API FRONTEND Added the AWS Glue data source (AWS Glue).
    • API FRONTEND Added the Google Sheets data source, which ingests spreadsheet tabs into feature groups with dltHub.
    • API FRONTEND Added chaining of on-demand transformation functions, where the output of one function feeds another, with a view of the chain on the feature group and feature view pages and from visualize_transformations() in the Python client, and n_processes of a feature group's insert and save to run independent transformations in parallel (also in 5.0.1).
    • API Added secondary indexes for online feature groups, declared with secondary_indexes in OnlineConfig of the Python client, or secondaryIndexes in the Java client, when the feature group is created (also in 5.0.1).
    • API FRONTEND HELM Added tags to jobs and apps (Job.add_tag and the other tag methods of Job in the Python client, and hops fv and hops job tags, add-tag and remove-tag), the time each tag and keyword was attached (get_tag_metadata and get_keywords_metadata of feature groups and feature views), and jobs, models, deployments, apps and agents to search; administrators can inspect and cancel stuck search index commands under Cluster settings > Service Operations (tags, search index).
    • API FRONTEND HELM Added Git repositories as a source for agent deployments (git_url, git_provider and git_branch of deploy_agent in the Python client), token prices per deployment to estimate the LLM cost (input_token_price_per_million_tokens and output_token_price_per_million_tokens of DeploymentTracingConfig), and dashboards of traces, LLM calls, tokens, cost and tool calls (agent deployments) (also in 5.0.1). Agent deployments now mount HopsFS, which on clusters with Kyverno needs hw-kyverno.policyExceptions.pythonDeployment.enabled (default true).
    • API FRONTEND Added Auto-redeploy on new commits to Python apps and agent deployments from a Git repository, which rolls them to each new commit of the tracked branch; set it with git_auto_redeploy in the Python client or --git-auto-redeploy of hops app create (apps).
    • API FRONTEND HELM Added an app base path, a proxy routing mode and a readiness probe path to apps, set in the Python client with app_base_path and readiness_probe_path of create_app, so an app can be served from its root without APP_BASE_URL_PATH; existing apps keep the prefix routing, and the App Metrics Grafana dashboard shows zero instead of "No data" for apps without traffic (also in 5.0.1).
    • API Added uploading a local script_file or config_file of a predictor or transformer to the project when the deployment is saved, such as by model.deploy(), in the Python client, and fixed updating a deployment's transformer script to a full HopsFS path failing with script not found.
    • API FRONTEND Added deleting rows from a feature group with remove_rows in the Python client and removeRows in the Java client, which delete from both stores of an online feature group unless storage is "offline" or "online"; online ingestion results and the ingestion activity in the UI show them as deleted rows (also in 5.0.8).
    • API Added project member management (Project.get_members, add_member, remove_member), feature group access for members with the Feature store restricted role (FeatureGroup.grant_restricted_access, revoke_restricted_access, get_restricted_access) and user administration (hopsworks.get_users_api()) to the Python client (users, members, sharing) (also in 5.0.8).
    • API Added OnlineIngestion.get_failures() to the Python client, which lists the rows an online ingestion failed to write and why, and changed inserts into online feature groups to fail when Kafka doesn't deliver a row, such as one over the broker's maximum message size, instead of only on authorization errors and timeouts.
    • API Added support for the storage argument of FeatureGroup.insert on stream feature groups, which ignored it with a warning: "online" now writes the rows only to the online store and "offline" only to the offline store.
    • API FRONTEND Added mandatory tags for models and deployments, and tags on deployments, which the Python client sets with Deployment.add_tag and reports in missing_mandatory_tags of a model or deployment (also in 5.0.2). Model tags move from HopsFS to the database the first time a model is read or tagged after the upgrade, and a tag that no longer matches its schema is dropped.
    • API FRONTEND Added key pair authentication to DLT ingestion from Snowflake, which accounts that enforce MFA need (Snowflake data source) (also in 5.0.14).
    • API FRONTEND HELM Added an upload policy, hopsworks.variables.upload_policy, that allows file uploads to everyone (enabled), to administrators only (admins_only) or to nobody (disabled), from the web UI and from clients such as the Python SDK; the web UI disables its upload controls for blocked users, and upload(overwrite=True) in the Python client no longer deletes the existing file when the policy blocks the upload (also in 5.0.8). The upgrade writes the value to the cluster, so a change made in the admin UI lasts until the next upgrade.
    • API FRONTEND Added the GitHub Copilot and OpenCode CLIs to the web terminal, next to Claude Code and Codex; the coding agents share the skills in your home directory, which hops skills list now lists, and keep their logins and sessions across terminal sessions (also in 5.0.10).
    • API FRONTEND Added GitHub Copilot as a provider of agent tasks, signed in with the token of a GitHub AI provider or of your github.com Git provider, which can't be a classic personal access token (also in 5.0.10).
    • API FRONTEND HELM Removed the per-project Hive database (<project>.db) and its quota from new projects; existing projects keep theirs.
    • API Changed model deployments, jobs, Jupyter servers and terminals to each get their own serving API key.
    • API Changed feature group schemas to be read from the Hopsworks database instead of the Hive Metastore; existing feature groups move over in the background after the upgrade.
    • API Changed GET /project/{id}/jupyter/running to return 204 No Content instead of 404 when no Jupyter server is running (also in 5.0.10).
    • API Changed import hopsworks to no longer import great_expectations when it is installed, which made the import take about 9 seconds instead of under 1.
    • API Removed the Python client's dependency on pyjks, which can't read JDK 21 keystores; the client now reads Java keystores itself.
    • API Changed training dataset creation on Spark to skip reading the written splits back when statistics are off (statistics_config=False), the slowest step for a large training dataset.
    • API Added the hops alert commands to the hops CLI, for the alerts and receivers of a project, job, feature group or feature view.
    • API Added --verify and --no-verify to the hops CLI, which turn hostname verification on or off as hopsworks.login(hostname_verification=...) does, also for the Trino connection of hops sql.
    • API FRONTEND Added Driver overhead factor and Executor overhead factor to the Spark configuration of jobs, Jupyter and project defaults, which set spark.driver.memoryOverheadFactor and spark.executor.memoryOverheadFactor, also as driver_memory_overhead_factor and executor_memory_overhead_factor of JobConfiguration in the Python client (PySpark jobs) (also in 5.0.12). Jupyter Spark sessions now default both to 0.4, as PySpark jobs do, so notebooks and their executors request more memory than before.
    • API FRONTEND HELM Added toolchain caches (HOPSWORKS_BUILD_CACHE), layer reuse for scripts that fetch nothing that changes (HOPSWORKS_BUILD_HERMETIC), when hopsworks.variables.docker_operations_allow_hermetic_custom_commands is "true", and secret references (NAME=secret:<secret>) to custom commands (custom commands).
    • API Fixed inserts into online feature groups waiting until the online ingestion timeout when the Python client writes some rows only to the offline store, such as earlier duplicates of a primary key or rows past the feature group's TTL; these rows now show as ignored.
    • API Fixed inserts with the upsert_if_newer online ingestion option failing for online feature groups with a composite primary key (also in 5.0.8).
    • API Fixed reads through the Hopsworks Query Service failing with "Could not read data using Hopsworks Query Service" when a filter on a numeric partition column meets a partition whose value is null, such as read_log of a feature view filtered by model.
    • API Fixed hops env install -f failing unless run from the project's mount; -f now takes a local requirements file, which it uploads to the project, or a path in the project.
    • API Fixed the Python client waiting forever on a library install or environment creation that never finishes; it now raises after waiting 30 minutes, also while the command is still running, so pass a larger timeout to create_environment, install_wheel, install_requirements or uninstall for longer installs.
    • API Fixed Trino connections of external Python clients with verify=True failing with unable to get local issuer certificate; they now verify against the cluster's CA.
    • API Fixed online feature vectors failing with a ValueError on TIMESTAMP(n) and DATETIME(n) features with fractional seconds, and similarity search results losing the milliseconds of timestamps (also in 5.0.8).
    • API Fixed SnowflakeConnector.connector_options() in the Python client failing for a data source with key pair authentication, and leaving out the role set on the data source (also in 5.0.14).
    • API FRONTEND Fixed the deployment test, the endpoint addresses and code snippets of deployments, their metrics dashboard, and predictions and endpoint URLs in the Python client using the project name instead of its Kubernetes namespace, which broke them on clusters with pre-created namespaces.
    • API FRONTEND Fixed model deployments with images from the managed Docker registry failing to start (also in 5.0.1).
    • API Fixed Project.project_namespace in the Python client always returning None.
    • API Fixed feature logging and feature monitoring on feature views with model-dependent transformations, such as one-hot encoding.
    • API Fixed model monitoring without a feature_name failing against a training dataset reference, because it also monitored the serving keys, predictions and logging metadata columns; it now monitors the model's training features.
    • API Fixed creating a training dataset with coalesce=True on Spark failing with SparkOutOfMemoryError, even on small datasets, when it has transformation functions or a time series split.
    • API Fixed training datasets created with the Python engine ignoring an external data source or path and being written to the default location.
    • API Fixed statistics computation on Spark failing on a numeric column whose values are all NaN, and computing a wrong histogram for a numeric column with any NaN.
    • API Fixed transformation functions defined inside another function failing with an IndentationError when applied.
    • API Fixed get_tag and get_tags of feature groups, feature views, training datasets, models and datasets in the Python client failing with a TypeError when a tag value is not a plain string, and get_tag of models always failing (also in 5.0.2).
    • API Fixed share, shared_with and unshare of feature groups and feature stores, and DatasetApi.unshare, failing in the Python client (also in 5.0.8).
    • API Fixed assigning Job.config in the Python client failing.
    • API Fixed creating an agent task with JobApi.create_job in the Python client failing with 'appPath' not set in job configuration (also in 5.0.10).
    • API Fixed find_neighbors in the Python client returning fewer than k neighbors when at least k rows match a filter or share the project's embedding index with other feature groups, for embedding feature groups created on 5.1.
    • API Fixed random splits of training datasets with the Python engine ignoring seed, so they were not reproducible (also in 5.0.2).
    • API Fixed importing the Python client reseeding Python's global random module (also in 5.0.2).
    • API FRONTEND Fixed feature statistics failing to save when a column has a NaN or infinite statistic, such as the standard deviation of an all-null column, statistics of DELTA feature groups being computed on the previous commit, and wrong uniqueness statistics, which are now left empty when exact_uniqueness is off (also in 5.0.9).
    • API Fixed API keys created by hops setup lacking the KAFKA, PYTHON_LIBRARIES, GIT, TRINO and SUPERSET scopes, so they could not insert into online feature groups.
    • API FRONTEND Fixed Ray jobs and the Ray clusters of Jupyter failing to start on OpenShift, because their pods couldn't read the project certificates (also in 5.0.9).
    • API FRONTEND Fixed adding a member to a project failing when feature groups are shared with that project (also in 5.0.1).
    • API FRONTEND HELM Fixed deleting a feature group failing after many online ingestions; Hopsworks now keeps the latest 1000 online ingestions of each feature group (cluster variable online_ingestion_max_per_featuregroup) (also in 5.0.2).
    • API Fixed offline reads of a feature view or query that includes a spine group failing with an HTTP 500 error (also in 5.0.13).
    • API Fixed reads of external feature groups in the Python engine failing when they leave out a feature appended to the feature group (also in 5.0.14).
    • API Fixed Snowflake reads through the Hopsworks Query Service, such as Python engine reads, using the Snowflake user's default role instead of the role set on the data source (also in 5.0.14).
    • API Fixed enabling feature logging failing with a duplicate column on feature views with two serving keys from one feature group, or with an event time as a serving key.
    • API FRONTEND HELM Fixed a read from an unreachable data source blocking with nothing logged; it now fails after 180 seconds (cluster variable arrow_flight_read_timeout_as_ms) with an error that names the data source.
    • API FRONTEND Fixed deleting a user right after deleting their projects failing with a generic error; it now returns a conflict that says to retry.
    • API FRONTEND Fixed failed or partly deleted projects counting against the owner's maximum number of projects (also in 5.0.1).
    • API FRONTEND Fixed ingestion with dltHub and schema fetching from NoSQL data sources failing when the project, data source or table names are long (also in 5.0.1).
    • API FRONTEND Fixed the state of a Spark or Ray job execution switching between queued and running while one of its pods couldn't be scheduled (also in 5.0.9).
    • API FRONTEND Fixed Git operations failing to authenticate when a provider token or password contains special characters (also in 5.0.10). The upgrade converts the saved credentials; if a provider still fails, save it again in your account settings.
    • API FRONTEND Fixed agent tasks that run at the same time failing to sign in to Claude Code, because they shared one credentials file (also in 5.0.10).
    • API Fixed Arrow Flight queries of partitioned DELTA feature groups failing once the feature group is older than delta.logRetentionDuration (also in 5.0.8).
    • API FRONTEND Fixed DLT ingestion rejecting a load whose decimal values are narrower than the precision of the source column (also in 5.0.14).
    • FRONTEND Fixed uploading files in the file browser deleting the files of the previous upload unless the page was reloaded (also in 5.0.10).
    • FRONTEND HELM Added file-based credentials, such as Oracle wallets, for user-created Trino catalogs: a project uploads them as mountable secrets, and a privileged sidecar on every Trino pod mounts /apps/mountable-secrets from HopsFS read-only (credential files).
    • FRONTEND HELM Changed environment builds to install libraries with uv when the image has it, to read the library list from the built image instead of starting three more Jobs, and to show the stage of a running build.
    • FRONTEND HELM Added npm packages to Python environments, installed globally and on PATH for jobs, Jupyter and the terminal; set hopsworks.variables.npm_registry_url to install from a registry other than registry.npmjs.org (installing libraries).
    • FRONTEND HELM Added the dbt-pipeline environment, with dbt and its Trino and DuckDB adapters.
    • FRONTEND HELM Added the online feature store (RonDB) quotas and memory usage to the project settings, a banner on project pages near or over quota, and a Quotas and Rate Limits page in the cluster settings for the defaults of new projects; HopsFS quotas are now labelled GB instead of TB, the unit they always had (also in 5.0.1).     Configuration changes#

    • HELM Changed hopsworks.variables.docker_operations_buildkit_extra_args to empty by default, dropping the S3 build cache arguments that failed without S3 credentials; set them again to keep an S3 build cache.
    • HELM Changed the default kserve.kserve.controller.deploymentMode from Serverless to Knative, its KServe 0.19 name.
    • HELM Added rondb.rondb.timeoutsMinutes.ndbmtdStartupProbe and rondb.rondb.timeoutsMinutes.mysqldStartupProbe, the startup probe timeouts of the RonDB data nodes and MySQL servers, and raised the MySQL server one from about 17 to 20 minutes (also in 5.0.5).
    • HELM Changed rondb.rondb.timeoutsMinutes.ndbmtdStartupProbe to 240 minutes, from 25 in 5.0.0 and 120 in 5.0.5, so data nodes that take over two hours to reload aren't restarted in a loop (also in 5.0.11).
    • HELM Changed the default spark.rss.shuffleServer.bufferCapacityRatio to 0.6 and spark.rss.shuffleServer.resources.limits.cpu to 2000m (also in 5.0.12).
    • HELM Changed hopsworks.variables.docker_operations_timeout_listing_minutes, docker_operations_timeout_check_minutes and docker_operations_timeout_export_minutes from 5 to 15 minutes, and max_concurrent_base_sync_ops from 6 to 5, so large base images finish syncing (also in 5.0.9).
    • HELM Changed the default Trino access rules, trino.trino.accessControl.rules, to let every user read the system.metadata tables; if you override the rules, add the same grant (also in 5.0.8).
    • HELM Changed the Superset init image to its own superset/dockerize repository, also in values.airgap.yaml; if you override superset.superset.initImage.repository, point it at a mirror of that image (also in 5.0.14).
    • HELM Changed the Prometheus adapter image repository to prometheus/prometheus-adapter, also in values.airgap.yaml; if you mirror images or override prometheus.prometheus-adapter.image.repository, mirror the new image.
    • HELM Changed the KubeRay operator image repository to hopsworks/kuberay-operator, also in values.airgap.yaml; if you mirror images or override ray.kuberay-operator.image.repository, mirror the new image.
    • HELM Changed the KServe controller image repository, kserve.kserve.controller.image, to kserve/kserve-controller instead of hopsworks/kserve-controller; if you mirror images or override it, mirror the new image.
    • HELM Changed values.openshift.yaml to turn off the Trino mountable-secrets sidecar (global._hopsworks.trino.mountableSecrets.enabled: false), which needs the privileged SCC, and to run Trino and its test coordinator under the UID the SCC assigns.
    • HELM Fixed users added to rondb.rondb.mysql.users after the install never being created, and users with privileges on a single database or table failing; every upgrade now creates the listed users (also in 5.0.11).
    • HELM Fixed the values schema rejecting a cron string in hopsworks.velero.backup.schedule.
    • HELM Fixed the chart failing to render with hopsworks.dropDatabase: true (also in 5.0.9).
    • HELM Added spark.spark-operator.hook.upgradeCrd (default true), a pre-install and pre-upgrade Job that updates the Spark operator CRDs from the hopsworks/spark-operator-crds:2.5.1-h1-1.9 image, also in values.airgap.yaml; if you mirror images, mirror that tag.
    • HELM Added spark.sql.ansiEnabled (default false), so SQL keeps returning null on overflow and invalid casts on Spark 4.1, as on Spark 3.5.
    • HELM Added hopsworks.dockerImage.pypi.pythonDownloads (default never), so uv never downloads a Python interpreter during environment builds.
    • HELM Added rondb.rondb.mysql.exporter.maxOpenConnections (default 1), the connections of the RonDB MySQL metrics exporter; the render fails if it exceeds rondb.rondb.mysql.exporter.maxUserConnections (also in 5.0.1).
    • HELM Added kafka.cluster.clusterCa.validityDays and kafka.cluster.clientsCa.validityDays (default 365) for the certificates Strimzi issues, applied at the next issuance (also in 5.0.10).
    • HELM Added kafka.cluster.kafka.quotas.type to choose the Kafka quota plugin: strimzi (the default), set under kafka.cluster.kafka.quotas.strimzi, or kafka, which enforces per-user quotas from kafka.users[].quotas and defaults from kafka.cluster.kafka.quotas.kafka (also in 5.0.13). kafka also needs kafka.cluster.kafka.quotas.minAvailableRatioPerVolume: 0, per-user quotas need kafka.cluster.kafka.authorizer.principalBuilderClass: "", which changes how ACLs and superUsers match principals, and none of these settings take effect on clusters first installed on Hopsworks 4.3 or 4.5.
    • HELM Added airflow.dependencies.mysql.ddlConsulServiceName (default mysqlddl), the DDL MySQL server the Airflow migration Job connects to (also in 5.0.13).
    • HELM Added global._hopsworks.wipeDataOnUninstall (default true) to delete the data volumes on helm uninstall (also in 5.0.2).
    • HELM Added cleanupOnUninstall.enabled to each component chart, such as hopsworks.cleanupOnUninstall.enabled, and certs-operator.gracefulCertTeardown.enabled, to turn off the uninstall cleanup of that component (also in 5.0.2).
    • HELM Added hopsworks.jupyter.notebookConfig.enableUploads; set it to false to block file uploads from the Jupyter UI and base64 uploads through the Jupyter Contents API (also in 5.0.8).
    • HELM Added global._hopsworks.initContainerResources (waiter, tool, runtime) to size the requests and limits that init containers now set (also in 5.0.9).
    • HELM Added olk.filebeat.kubernetesMetadata, the pod, namespace and node labels Filebeat keeps on service logs (extraPodLabels, extraNamespaceLabels, extraNodeLabels for your own), and addKubernetesMetadata on each olk.filebeat.logs_locations entry (also in 5.0.12).
    • HELM Added hopsworks.velero.backup.storageLocation.s3ForcePathStyle for S3-compatible backup stores that need path-style addressing (also in 5.0.1).
    • HELM Added hopsfs.objectStorage.s3.disableCertChecking and hopsfs.objectStorage.s3.disableChecksumValidation to turn off TLS certificate checks and client-side checksum validation for the HopsFS S3 endpoint (also in 5.0.3).
    • HELM Added hopsworks.variables.docker_operations_lock_dependencies, docker_operations_allow_hermetic_custom_commands and docker_operations_multi_region_copy, off by default, for hash-locked build dependencies, cached hermetic custom commands and image copies to the second region.

    • HELM Added kserve.knative.imageRegistry for the Knative images.
