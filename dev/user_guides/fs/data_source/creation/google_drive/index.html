    How-To set up a Google Drive Data Source#

    Introduction#

    A Google Drive data source connects a Hopsworks project to a folder in Google Drive, in a user's My Drive or in a shared drive. It does not back feature groups and cannot be read with Spark. Instead, it is the source of a files ingestion job, which copies the files under the folder, whatever their format, into a dataset of the project, either once or on a schedule, with optional mirroring of deletions and a file index feature group.

    Hopsworks reads the folder as a Google Cloud service account, through the Google Drive API with the read-only scope drive.readonly, with the dltHub filesystem source in read-only mode. Data only flows from Google Drive into Hopsworks. Changes made in the dataset are never written back to Drive.

    Prerequisites#

    Service account and key file#

    Hopsworks authenticates to Google Drive with a service account of a Google Cloud project:

    1. In the Google Cloud console, pick or create a project and enable the Google Drive API in it. Requests of a project without the API enabled are refused, whatever the folder is shared with.
    2. Under IAM & Admin, then Service Accounts, create a service account. It needs no role in the Google Cloud project; its access to the files comes from sharing the folder with it.
    3. Open the service account, and under Keys add a new key of type JSON. Download the key file; it is the only copy. See Create service account keys for the details.
    4. Note the service account's email, <name>@<project>.iam.gserviceaccount.com, which is also the client_email field of the key file.

    The key file is uploaded to the Hopsworks project when the data source is created, and deleted with it.

    Folder#

    Share the folder with the service account's email, as a Viewer. Hopsworks only lists and downloads, so viewer access is enough. The service account is its own Google identity: a folder in your My Drive is invisible to it until it is shared, even though the service account's key was created in your Google Cloud project.

    1. In Google Drive, right-click the folder and choose Share.
    2. Enter the service account's email, <name>@<project>.iam.gserviceaccount.com, and pick Viewer.
    3. Untick Notify people, since the service account has no inbox, and click Share. Google may warn that the address is outside your organisation; confirm it.

    A Google Workspace administrator can block sharing with addresses outside the organisation; in that case put the folder on a shared drive and add the service account as a member of it.

    For a shared drive, add the service account as a member of the shared drive, as a Viewer, or share one of its folders with it. Shared drives are reached through the same data source; nothing else is needed.

    Copy the folder ID from the folder's URL in the browser: it is the last part of https://drive.google.com/drive/folders/<folder ID>, a string of letters, digits, - and _. The root of a shared drive has an ID of the same form, in the URL of the shared drive. The data source stores the ID, since folder names are neither unique nor stable; the folder name entered next to it is only shown in the UI.

    Client version#

    The Python client and the hops CLI support Google Drive data sources from Hopsworks 5.3.0. Clients older than 5.3.0 do not know the Google Drive type and fail to list a feature store's data sources once it has one, so upgrade the client in environments that list data sources.

    Creation in the UI#

    Step 1: Set up a new data source#

    Head to the Data Sources view in Hopsworks and click New data source. Pick the Google Drive card, in the Files & documents category.

    Step 2: Enter the folder and the key file#

    1. Name and an optional Description.
    2. Service account key file: upload the JSON key file from your machine with Upload new file, or pick one already in the project with From Project.
    3. Folder ID: the ID copied from the folder's URL.
    4. Folder name: an optional label shown next to the ID in the UI; it is not used to find the folder.

    Click Test connection to check the key file. Hopsworks reads it from the project and checks that it is a service account key, with a client_email and a private_key, and answers with the service account's email and a reminder to share the folder with it, such as Service account ingest@acme.iam.gserviceaccount.com; share folder 1AbCdEfGhIjKlMnOpQrStUvWxYz with it. The test does not call Google Drive, so a folder that is not shared with the service account, or a project without the Drive API enabled, is only found by the first run of a files ingestion job; see Troubleshooting for the messages such a run shows.

    Click Next to save the data source and go on to the second step of the wizard, Copy files into a dataset, described in the files ingestion guide. The Browse button of the prefix is not available for Google Drive, so type the prefix.

    Editing the data source#

    The data source page shows the folder ID, the folder name, the key file path and the service account's email read from the key. Pick another key file to rotate the credentials; the next run of each files ingestion job uses it.

    Using the Python client#

    The key file must be in the project before the data source is created; upload it with the dataset API.

    import hopsworks
from hsfs.storage_connector import GoogleDriveConnector


project = hopsworks.login()
fs = project.get_feature_store()

key_path = project.get_dataset_api().upload("drive-sa.json", "Resources")

drive = fs.create_data_source(
    GoogleDriveConnector(
        id=None,
        name="handbook_drive",
        featurestore_id=fs.id,
        key_path=key_path,
        folder_id="1AbCdEfGhIjKlMnOpQrStUvWxYz",
        folder_name="Handbook",
    )
).storage_connector

print(drive.service_account_email)  # from the key file; share the folder with it

job = drive.ingest_files(dataset="handbook", prefix="2026/")

    key_path is the path of the key file in the project, as returned by upload, or written out as /Projects/<project>/Resources/drive-sa.json. service_account_email is read-only and filled by Hopsworks from the key file.

    Using the CLI#

    hops datasource create google-drive handbook_drive \
    --key-file ./drive-sa.json \
    --folder-id 1AbCdEfGhIjKlMnOpQrStUvWxYz --folder-name Handbook
hops datasource ingest-files handbook_drive --dataset handbook --prefix 2026/

    --key-file is the key file on your machine; the command checks that it is a service account key, uploads it to Resources/datasources/<name>/ in the project and registers the data source with that path. For a key already in the project, pass its full HopsFS path with --key-path instead.

    Next steps#

    Copy the files under the folder into a dataset with a files ingestion job. The prefix of the job is a folder path below the shared folder, by folder names, and a run reads gdrive://<folder ID>/<prefix>, so an empty prefix copies the whole shared folder. The index feature group, when turned on, records gdrive in source_type and the same gdrive:// URL in source_url.

    Troubleshooting#

    A run that cannot reach the folder fails before listing anything. Its execution on the job page shows root path '<folder ID>' not found or not readable followed by Google's answer, and the same text is in the execution logs. The answer tells which step of the setup is missing:

    Google's answer Cause Fix
    HttpError 403 ... Google Drive API has not been used in project <number> before or it is disabled The Drive API is not enabled in the Google Cloud project the service account belongs to. Enable it at the link in the message, or in the API library. Wait a few minutes for the change to propagate, then re-run the job.
    HttpError 404 ... File not found: <folder ID> The folder is not shared with the service account, or the ID is not a folder's ID. Drive answers not found for anything the caller cannot see, so an unshared folder looks the same as a wrong ID. Share the folder with the service account's email as described under Folder, or add the service account to the shared drive. Check the ID against the folder's URL. The service account's email is shown on the data source page.
    HttpError 403 ... insufficientFilePermissions or cannotDownloadFile on a file The service account sees the folder but not that file, or the file's owner has disabled downloading for viewers. Share the file, or turn Viewers and commenters can download back on; otherwise the file is counted as failed and the rest of the run goes on.
    RefreshError: invalid_grant: Invalid JWT Signature The key in the uploaded JSON file is no longer valid: it was deleted or rotated in the Google Cloud console, or the service account was disabled. Create a new JSON key for the service account, upload it, and pick it as the key file of the data source. The next run uses it.
    RefreshError: invalid_grant: Invalid grant: account not found The service account was deleted. Create a service account and key again, share the folder with the new email, and update the data source.

    A file_cache is only supported with oauth2client<4.0.0 line at the top of the logs is a notice of the Google client library and not an error.

    Limitations#

    • A Google Drive data source is read-only and files-only. It backs no feature groups, cannot be read with Spark, and the dltHub table ingestion does not offer it.
    • Only files stored in Drive are copied. Google Docs, Sheets, Slides, shortcuts and the other Google-native items have no file content to download, and the job does not export them; they are counted as unsupported, listed in the audit file and left out, without failing the run. Files in the trash are not listed. Two files with the same name in one folder are told apart by appending the Drive file ID to the later one; a file whose name contains a slash is counted as unsupported. Exclude them with an exclude pattern on their names, or keep them in a folder outside the prefix.
    • Files are copied one at a time and the folder tree is listed in full on every run, so a very large folder is better split into several jobs with narrower prefixes.
    • Browsing the folder for a prefix is not available; type the prefix, as a path of folder names.
    • Test connection only checks the key file; sharing and the Drive API are checked by the first run, see Troubleshooting.
